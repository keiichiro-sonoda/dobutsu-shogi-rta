# 記録を取らない実験と門番の作法

`experiments/` を触るときに読み込まれる。CLAUDE.md の「記録を取らない実験」の続き。
経緯と数字は [`docs/lessons.md`](../../docs/lessons.md) にある。

## 置き方

- `baseline/` `impl/` と同じく、フォーマッタと自動修正フックの対象外にしてある
- 生ログにホスト名・ユーザー名を含むパス・ほかのプロセスの名前を残さない（CLAUDE.md の
  「記録に残さないもの」）。回す前の負荷は load average と CPU 使用率の合計だけを残す
- 止めたときは調査用に `runs/` の `dat/` を残し、止めた回の生ログは `logs/aborted/` に分けて残す

## 門番の作り方

- **門番は完走単位で、`old new new old` を並べる。**
  `numactl --cpunodebind=0 --membind=0` で固定する
- **各本の前にノード0の空きを確かめる。** 起動前やキャッシュを落とす前後に手で読む値も、
  `free_snapshot.sh` のようなスクリプトでファイルに残す（手で読むだけの値を作らない）
- **`old` 腕には、変数に数えない変更（計装・片付けなど）も入れる。** 片方の腕にだけ入ると、その差が
  レバーの効果に混ざる。「`old` ＋ レバーのパッチ ＝ 記録の実装」をテストで固定する
- 腕の `.so` の sha256 を進行ログに出す。C を足すと後ろの関数の番地がずれて、
  触っていない段が動きうる
- **判定の量・止める条件・予測は、回す前にコミットする。** 結果は README に追記し、外れた予測も書く
- 各本のあとにその場で見る: オラクル174行、`dat/` の md5 一覧の sha256 (記録の証拠から読む)、
  `forward.tsv` の件数の列、`thp_fault_fallback`。どれかに掛かったら `dat/` を残して止める
- 比較が1対1なら補正は要らない。腕が多い回（lever_scan など）の値は多重比較未補正なので、
  記録にするときは記録にする版そのものを門番で測り直す。差どうしを引き算して偏りを出さない

## 入力の揃え方

- **組み直したフィクスチャは採番順を復元しない。** `tools/rebuild_forward_fixture.py` は集合を
  戻すが並びは戻さない。後退解析の門番の入力は、全探索の出力をそのまま使う
- **#22 から後退解析はファイルを読まない。** 門番は完走で測るか、門番側の driver が
  `dat/` を読んで渡す: `unknown*` を番号順に連結して `uk_all` に、`win001te_*` / `lose000te_*` を
  `catch_wins` / `try_loses` に置き、`unknown*` を消してから `retreatAnalysis()` を呼ぶ
  （`tests/conftest.py` の `seed_memory()`）。
  **読み込みは門番の側に置き、実装に戻さない**
- 採番順に反応する段（P4 の乱書きなど）の効果量を「本走の値」として書かない。
  旧新を同じ入力で交互に比べるぶんには影響しない
