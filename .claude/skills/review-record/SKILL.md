# このリポジトリ固有のレビュー

観点は [`docs/review-checklist.md`](../../../docs/review-checklist.md) にある。
**本文をここに写さない。** 同じものを2か所で持つと、片方が腐って気づけなくなる。

## 手順

1. `docs/review-checklist.md` を読む
2. 対象の差分を出す（既定は `git diff origin/main..HEAD`。PR 番号やパスを渡されたらそちら）
3. チェックリストの節ごとに差分を当てる
4. 指摘を2つに分けて出す
   - A: `make publish-check` が止める種類（鍵・同定情報・凍結物・証拠）。push しない
   - B: それ以外（説明の誤り・数字の不一致・命名）。直すが push は止めない

## 読み方

この3つを守らないと、チェックリストを持っていても同じ外し方をする。

- **主張を見たら、その主張が指しているファイルを開く。** 差分の外にあっても開く。
  記録 #13 の `out[3]` の誤った説明は、否定する証拠が凍結側の C にあった
- **変わった数字は、リポジトリ全体を grep する。** 記録表・frontmatter・ノート本文・
  「次の標的」のレバー表は同じ値を持つ。1か所だけ直すと残りが嘘になる
- **テストは数えない。何を呼んでいるかを読む。** 緑が「覆っている」のか
  「挟んで外している」のかは、本数からは分からない

## 機械が見る側と重ねない

`make publish-check`（`tools/publish_lint.py`）が、鍵・同定情報・凍結物の変更・
記録の証拠の欠損・`Claude-Session:` 行を見る。そちらで落ちるものをここで探さない。
