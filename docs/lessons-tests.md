# 取り決めの経緯: テスト

[`lessons.md`](lessons.md) の続き。[CLAUDE.md](../CLAUDE.md) の「チェック」の節の規則を、なぜそう決めたかと、
そのときの数字。

### コミットのフックは、変わったものに関係する重いテストだけを回す

コミットのたびの `pytest` が 213 秒になった（#38 の時点）。ほとんどは凍結した実装どうしの比較で、実装もテストも
変わらなければ何度回しても同じ（実装が変わらないことは `test_recorded_impls_frozen` が毎回見る）。そこでフックは
`tools/select_tests.py` で、足した変更が入力に当たる重いテストだけを回す。土台・依存・`baseline/`・`oracle/`・
分類できない場所が変わったら全部回す。道具の版の変化は、毎回全部を回す CI（公開なので無料）が受け持つ。

### テストのメモリは版ごとに積み上がっていた（#39 で CI が止まった）

`ctypes` で読み込んだ `.so` はプロセスが終わるまで外れない。#34 から C の側は番号の範囲全体の配列
（発見済みの表 約 107 MB、`g_prep`・`g_dtm` 各 約 855 MB）を確保して埋めるので、打ち切った走行でも
1つの `.so` で約 1.8 GB を触り、版のテスト（その版と1つ前の版を読む）が1つで約 3.2 GB 積み上がる。
pytest は一式を1つのプロセスで回していたので、`test_impl_34`〜`39` で 17.6 GB（計測機で測った。
1ファイルずつなら最大 3.25 GB）、一式で 24.9 GB になっていた。

CI（GitHub の `ubuntu-latest`、16 GB）は記録 #39 の push（`be066dd`）から落ち続けた。テストが失敗したのではなく、
3回とも `test_impl_39_rank_lean.py` か `test_dtm_ahead.py` のあたりで `make: *** [Makefile:44: test] Error 137`
（SIGKILL）と `The runner has received a shutdown signal` で止まり、ステップは「The operation was canceled.」になった。
ランナーのイメージは3回とも `ubuntu-24.04` で、版の移行は関係なかった。一式を手元で上限なしに回すと、
ほかのアプリまでメモリ不足で落ちることがある。

直し方は「`.so` を読み込むテストのファイルを1ファイル1プロセスで回す」にした（`tools/run_tests.py`）。
テストの書き換えが要らず、版のテストがいくつ増えてもピークは1ファイルぶんで止まる。テストごとに fork する案は、
モジュール単位のフィクスチャ（打ち切った走行）がテストごとに走り直して遅くなるので取らなかった。
軽いテストはまとめて1プロセス、カバレッジは `--cov-append` して最後に1回 `coverage report`。`make check`・CI・
コミットのフック（`select_tests.py --run`）・`make test-staged` が同じ道具を通る。プロセスごとのピークの RSS
（`wait4` の `ru_maxrss`）が 8 GiB（ランナーの半分）を超えたら落とすので、次に積み上がったら黙って CI を止めずに
その場で分かる。

| | 直す前（1プロセス） | 直したあと |
|---|---|---|
| `test_impl_34`〜`39` ＋ `test_dtm_ahead` | 24 GB の上限で止められた（`34`〜`39` だけで 17.6 GB） | プロセスごとの最大 6.42 GiB（`test_dtm_ahead`） |
| `make check` のピークの RSS | 24.9 GiB | 6.43 GiB（34 プロセス） |
| `make check` の時間 | 3 分 8 秒 | 3 分 30 秒（1.12 倍。`.so` のビルドをプロセスをまたいで使い回せない分） |
| テストの数 | 2621 個を集めて 2621 個が通った | 2634 個を集めて 2634 個が通った（前の 2621 個は全部そのまま。足したのは `test_run_tests.py` の 9 個と、この文書を足して増えたリンクの検査 4 個） |

いちばん重いのは `test_dtm_ahead.py`（4つの `.so` を読む）で、上限の 8 割。1つのファイルでこれ以上 `.so` を
読むときは、ファイルを分ける。
