## 段の推移

#13 で F1 が 246 秒、#14 で174段ループが 177 秒、#15 で P2 が 88 秒縮んだ。**局面ごとの FFI 往復はこれで全部消えた。**
#16 で保存形式を pickle から生バイナリに変え、**読み書きの塊も畳んだ**（F0 53 → 1 秒、P0 95 → 3 秒）。
#17 で書き出しの `set(...)` を外し、**書く側の `PyLong` も消えた**（F5 160 → 13 秒、F2 111 → 11 秒、F6 54 → 2 秒）。
#18 で `-O0` をやめた（F1 154 → 98 秒、P2 96 → 62 秒）。
#19 で連番→パック値の翻訳をC へ移した（門番で174段ループ **−18.0 秒**、引き分けの抽出 **−4.2 秒**）。**Python 側で億単位に触る場所はもう1つも無い。**
#20 で C の4か所に先読みを入れた（P4_scatter 58 → 13 秒、F1 99 → 84 秒）。
#21 で2つの表を巨大ページにした（P2 63 → 46 秒）。
#22 で全探索の中間ファイルをやめた（F0＋F2＋F5 31 → 2 秒、P0 4.0 → 1.4 秒）。
#23 で174段ループに先読みを入れた（27 → 16 秒）。
#24 で展開の作業用配列を使い回した（F1 76.5 → 72.8 秒）。
#25 で後退解析の配列を巨大ページにした（P4 19.3 → 15.7 秒）。
#26 で盤面の反転をループ無しにした（F1 73.6 → 66.6 秒、P2 45.4 → 42.3 秒）。
#27 で `-fno-semantic-interposition` を足した（F1 66.6 → 64.2 秒）。
#28 で `-march=native` を足した（F1 64.2 → 62.7 秒、P2 41.9 → 40.0 秒）。
#30 で発見済み表をランクで引くビット表にした（F1 62.7 → 50.3 秒）。
#32 で `rankOf()` をインライン展開した（門番で F1 −0.4 秒、P2 は置き場所で +0.6 秒）。
#33 で熱い関数の置き場所を固定した（門番で F1 −0.4 秒、P2 −0.5 秒。命令は同じ）。

## 何が残っているか

**残っているのは全部 C の中。** いちばん大きい **F1 展開**と **P2 後続生成**は同じ関数（`nextBoardInvNormal`）を共有していて、#18 の `-O2`、#26 の盤面の反転、#27 の `-fno-semantic-interposition`、#28 の `-march=native` が効いたのもそこ。
#21 の巨大ページはこの2段が引く表（発見済み表と索引）に効いた。
#22 で全探索の書き込みの待ちが消え（11.2 → 0.0 秒）、全探索も後退解析もほぼ CPU 律速になった。
#24 で F1 の作業用配列を使い回し、F1 のカーネル時間は 4.8 → 3.0 秒になった（本走）。
#30 で発見済み表の作り直しが無くなり、0.8 秒になった。
#25 から段ごとの minor fault が出ていて、F1 はフォルト1回あたりのカーネル時間が F2・F5 の約5倍ある（[ノート](records/25-huge-retreat.md)）。
[`experiments/gen_bench/`](../experiments/gen_bench/)（記録ではない）で生成器だけを局面の種類ごとに測り、候補 B（盤面の反転）を #26 で記録にした。
マイクロベンチの換算の 77% が本走の門番で出た。
CSR をランダムに舐める段は、#20・#23 の先読みと #25 の巨大ページで P4 **15.7 秒**、174段ループ **14.5 秒**になった。

## レバー表

## 見込みと実測の振り返り

### `-O2` の見込み

**`-O2` は #18 で引いた。実測は完走 −109.88 秒（−25.3%）。**
2026-09-13 のマイクロベンチは
`C単体 -O0 0.1597 → -O2 0.1071（1.49倍）`、`本物の経路 -O0 1.4964 → -O3 1.3642（8.8%）`で、
**糊が薄くなるほど C の比率が上がるので後になるほど効く**と書き残してあった。
⚠️ **向きは当たり、大きさは当時の見積りを大きく超えた。** 全探索合計で
**−30.5%**、C 単体に近い F1 単独では **154 → 98 秒（1.56倍）**で、
むしろ「C単体 1.49倍」のほうに寄った。#8・#11・#12・#13・#14・#17 と糊を
薄くし続けた結果、本物の経路が C 単体に近づいていた。

「1本で測れるとは書けない」という但し書きも当たっていた。段の選択（`-O2` 対 `-O3`）は
差が 0.24 秒で、完走タイム1本ではどうにもならない。**5腕 × 4本を全探索合計で
比べて決めた**（[`gate_18_opt`](../experiments/gate_18_opt/)）。

### 採番順の見込み

⚠️ **採番順のレバーは #12・#13・#14 で前提が変わった。** P4 も展開ループも174段ループも
C 側へ移ったので、[`experiments/numbering_order/`](../experiments/numbering_order/) が測った
「並べ替えで P4 が 88 秒縮む」という引き算はもう成り立たない（P4 自体が 157 秒）。
**測り直しが要る。**

**採番順のレバーは #8 でも見込みが変わっていた。**
[`experiments/numbering_order/`](../experiments/numbering_order/) では F（上位ビットのバケット）が
A に対して −104 秒と出たが、その得の半分以上は P2 から来ていた。その P2 が 1,035 → 194 秒に
なったので、**同じ引き算はもう成り立たない。**

### 1本の壁時計

⚠️ **どれも、1本の壁時計だけでは効果量を確定しにくい大きさに近づいている。**
**フェーズ単独を複数回測る門番のほうが、観測を増やせるぶん分が良い。**
ただしフェーズ単独の帯は合計の帯より広い（#8 で P1 が 11.8% 振れた）。

## 初期の記録を取らない実験

レバーを引く前に、効果量だけ先に測ることがある。⚠️ **入力を固定してフェーズ単独を
走らせる比較なので、レギュレーション（空の `dat/` から完走）を満たさない。
タイムを README の記録表に載せない。**
