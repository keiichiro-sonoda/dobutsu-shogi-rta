## 改善を示唆する観測はある（ただし確定はしていない）

⚠️ **#6 の全探索 2,396 秒は、同一コード6本のうち最速の観測だった。** そこを基準にすると
改善が過小に出る。コードのバージョンごとにまとめ直すとこうなる:

| | 観測 | 平均 | ばらつき |
|---|---|---|---|
| `impl/03`〜`06` の全探索 | 2396 / 2430 / 2436 / 2443 / 2503 / 2523 | **2,455 s** | sd 48 s |
| `impl/07` の全探索 | 2237.6（門番）/ 2315（本走） | **2,276 s** | 幅 77 s |

**平均の差 179 秒（標準誤差 43 秒）。** 点推定は登録した予測 150〜250 秒のなかにある。

⚠️ **ただしこれは「効果が確定した」という意味ではない。** 旧版6本・新版2本を独立標本として
Welch の方法で検定すると、**自由度 1.56 / 両側 p = 0.081 / 95% 信頼区間は −69 〜 427 秒**。
新版の観測が2本しかないので区間が 0 をまたぐ。**t = 4.12 という数字だけを見て
「分離できた」と書いたのは誤りだった**（自由度を計算していなかった）。

🔑 **時間ではなく、直接測れるもので裏は取れている。** ディスク書き込みは
**9.44 → 7.36 GiB** に落ちた（予測 7.2〜7.5 GiB）。消した書き出しは 246,005,718 要素 ×
実測 9.0〜9.2 B/要素 = 2.1 GiB で、**設計どおりの入出力が実際に消えたことは確かめられている。**
確定していないのは「それが何秒に相当するか」である。

同じことが対照群側にも言える。**同一の後退解析コードの観測は3本ある**:

```
2,087 s (#6 本走) / 2,144 s (#6 の門番) / 2,156 s (#7 本走)    幅 3.3%
```

#7 の 2,156 秒はこの幅のなかに収まる。#6 の1本だけを基準に ±3% の帯を引いたのが狭すぎた。

⚠️ **ただし「雑音だった」と断定はできない。** #7 は勝ち／負けファイルのチャンクの中身が
変わるので、後退解析が読む `packed[]` の並びも、そこから作る 24.41 GiB の辞書の配置も変わる。
**+69 秒のうち +66 秒が P2（辞書を作って 9.4 億辺を引く段）に集中している**ことは、
雑音と読むことも、配置の変化が効いたと読むことも、**この1本からはどちらもできない**。

## 🔑 今回の計測本数では効果量を確定できなかった

点推定 179 秒は 4,500 秒の走行の約 4% で、計測機の観測幅は 5.3% ある。
**同じ大きさのものを重ねて見ていることになり、今回の本数（旧版6本・新版2本）では
どちらがどれだけ効いたかを切り分けられなかった。**

⚠️ **これは「約4%が検出限界だ」という意味ではない。** 観測の幅から検出限界は決まらない。
本数を増やせば同じばらつきのままでも区間は狭くなる。言えるのは
**「今回の本数では確定できなかった」**まで。

- 門番 G1（全探索だけを完走）は同じ条件を作り直せるので、観測を増やす道がある
- 記録表のタイムは「1本の壁時計」と決めてあるので、そこには平均も区間も出ない

⚠️ **記録は 1:14:31 のままで正しい。** レギュレーションがそう決めている以上、
「平均で見れば速い」はタイムにしてはいけない。ここに書いて残すのが正しい扱いになる。
