# 記録 #8 で分かったこと

**後退解析が半分以下になった。** 2,156 秒 → **1,150 秒（−46.7%）**。合計は 1:14:31 → **0:58:40** で、
初めて1時間を切った（9.13×）。

消したのは「パック値 → 連番」の照合そのもの。#7 までは 2.4 億件の Python `dict`（24.41 GiB）で
引いていて、キャッシュに全く乗らないので1回に約 0.85 µs かかっていた。
C側にオープンアドレス法の平坦な表（16 B × 2²⁹ スロット = 8.59 GB、占有率 0.46）を置き、
指し手生成と索引引きを**既存の1回の FFI 呼び出しの中**で済ませた。

| 段 | #7 | #8 | 差 |
|---|---|---|---|
| P0 読み込み | 95 s | 94 s | −1 |
| **P1 索引** | 167 s | **20 s** | **−147** |
| **P2 後続生成** | **1,035 s** | **197 s** | **−838** |
| P4 前任リスト | 546 s | 545 s | −1 |
| 174段ループ（⚠️ 表示値の合計＝下限） | 264 s | 258 s | −6 |
| 残差 | 49 s | 36 s | −13 |
| **後退解析 合計** | **2,156 s** | **1,150 s** | **−1,006** |

⚠️ **174段ループの行は実時間ではない。** 深さごとの所要時間は `s2hms()` が秒未満を切り捨てて
出すので（#8 では174行のうち **145行が「00分00秒」**）、258 秒は**表示値の合計＝下限**にすぎない。
上限は「後退解析 − 測った4段」＝ **294 秒**で、あいだに残差（`indexFree()` によるメモリ解放、
`dtm` の確保と初期化、引き分けの抽出と書き出し、端数）が入る。
**#8 のループ実時間は 258〜294 秒。** 上の「−6 秒」も**表示値どうしの差**であって、
実時間の差ではない（#7 の 264 秒も同じく下限）。

辺の総数は 938,671,869（未発見の後続 0）で #7 と一致。**オラクル174行 PASS、
記録 #7 の `dat/` と指紋176項目が一致**（246,803,167 局面）。

## 🔑 FFI の回数を増やさないことが前提だった

⚠️ **`rank(board)` のような関数を作って辺ごとに ctypes で呼んだら、この改善は消えていた。**
呼び出し1回が約 1 µs（README:158 の実測）で、辞書引きは約 0.85 µs。9.4 億本に個別に呼ぶと
**今より遅くなる**。呼び出し回数は未知盤面の数 **99,485,568 回のまま**動かしていない。

⚠️ **境界をまたぐデータをバイト列のまま運ぶことも前提だった。** ctypes 配列のスライスは
PyLong を n 個作るので、9.4 億個ぶん作ったらC側に移した意味が消える。
**記録 #1 で 1.36× を失いかけたのと同じ罠**で、`memoryview` 経由で `array.frombytes` に繋いでいる。

## 対照群の全探索が +4.1% 出た。これは退行ではない

全探索は**1バイトも変えていない**（`tests/test_impl_08_c_index.py` が #7 とのバイト一致を検査する）。
それでもタイムは動いた。

```
同一コードの全探索: 2,237.6 s (#7 の門番) / 2,315 s (#7 本走) / 2,370 s (#8 本走)
平均 2,307.5 s、幅 5.9%（最小値基準）
```

⚠️ **#8 の 2,370 秒は、直前までの2本の平均（2,276 秒）に対して +4.1% で、±3% の帯の外に出る。**
だが同一コードでこれだけ振れるのだから、**帯のほうが狭すぎた**。
古いコードの全探索も6本で 5.3% 振れている。**記録 #7 で「前回の1本を基準に ±3% を引いて
+3.3% を退行と読みかけた」のと同じ形**なので、ここでは退行と読まない。

## 段ごとの振れは、合計の振れより大きい

⚠️ 門番 G1a（`experiments/ffi_buffer_reuse/`）で、**`buildIndex` を1バイトも触っていない P1 が
161 / 167 / 180 秒（11.8%）振れた。** 後退解析**合計**の振れは 3.3% なので、
**フェーズ単独の差を読むときに合計の帯（±3%）を流用してはいけない。**
⚠️ 一方 P4 は 1.7% しか振れていない。**段ごとに帯が違う。**

⚠️ **並べてよいのは、その段のコードがバイト同一な観測だけ。**
G1a は `buildSuccessors` を変えているので、**G1a の P2 と後退解析合計は
「同一コードのばらつき」に入れてはいけない**（評価しようとしている測定そのものを
雑音の基準に使うことになる）。

| 段 | 同一コードの観測 | 本数 | 幅 |
|---|---|---|---|
| P1（辞書構築） | 161 (#6) / 167 (#7) / 180 (G1a) | 3 | **11.8%** |
| P2（後続生成） | 969 (#6) / 1,035 (#7) | **2** | 6.8% |
| P4（前任リスト） | 554 (#6) / 546 (#7) / 550 (G1a) / 548 (G1b) / 545 (#8) | 5 | 1.7% |
| 後退解析 合計 | 2,087 (#6) / 2,144 (#6門番) / 2,156 (#7) | 3 | 3.3% |

⚠️ 幅は **(最大 − 最小) ÷ 最小**（記録 #5 以降と同じ基準）。
⚠️ P1 と P4 に G1a・G1b・#8 を入れているのは、**その段のコードが #7 とバイト同一**だから。
ただし前の段の中身は違うので、まったく同じ条件の観測ではない。
⚠️ **どの幅も2〜5本の観測で、ばらつきの上限ではない。**

## バッファ確保のぶんは分離できなかった

今回の変更は「48要素の ctypes 配列を未知盤面ごとに確保する」のもやめている
（梯子では別のレバーとして数えていた）。辞書を残したままバッファ再利用だけを入れた版で
後退解析を1本走らせたが、**P2 は 1,035 → 1,033 秒（−2 秒）**で、P2 の振れ幅（約 66 秒）の内側だった。

⚠️ **「効果が無い」ことを示したのでも、「寄与が小さい」ことを示したのでもない。**
各1本の比較なので、言えるのは「**今回の観測差は −2 秒。寄与率は未確定**」まで。
⚠️ 辺ごとの PyLong 生成（9.4 億個）は辞書引きと不可分で、そもそも分離できない。
**−838 秒の内訳は分かっていない。**
詳細は [`experiments/ffi_buffer_reuse/`](../../experiments/ffi_buffer_reuse/)。
