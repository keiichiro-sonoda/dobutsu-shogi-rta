## ③を外した理由：Cの探査は「ただ」ではないが、Python のオブジェクト生成が減った

9.4 億回の登録を足して **正味 +48.6 ns/回**（門番では +30.4 ns/回）。
C の探査を 0.15〜0.25 µs/回と見積もっていたので、**4倍以上外している。**

分離はしていないが、**同じ変更で PyLong の生成が 9.4 億個 → 2.5 億個に減っている**
（初見だけが返るため）。#10 の当てはめでは生成1要素あたり 75.1 ns だったので、
**減ったぶんが約 −52 秒**。これが C の探査の実費と相殺していると読める（**推定**）。
⚠️ **2つを分けるには、登録だけして全部返す版を別に走らせるしかない。やっていない。**

## ⚠️ F5 が 86 秒速くなった理由は分かっていない

未探索チャンクの書き出しは**1バイトも変えていない**のに、269.59 → 183.26 秒（−32%）。
門番（181.13 秒）でも同じ水準なので、**雑音ではない。**

**推定**: #10 では `new_unexp_boards` が `list(set(...))` で、**要素の並びが集合の反復順**
（＝メモリ上はばらばら）だった。#11 は生成順のリストのままなので、F5 が
「スライス → `set()` → `pickle`」と2回舐めるときの局所性が良い。
⚠️ **確かめていない。** 確かめるなら #10 の F5 に入る直前でリストを並べ替える実験が要る。

## ⚠️ 既知の不具合：C側の確保失敗を握りつぶす

`nextBoardSeenNormalWrap` は C の戻り値 `-3`（表を確保できない）を検査していない。

扱われ、その局面の後続が探索キューに入らないまま静かに先へ進む。**
