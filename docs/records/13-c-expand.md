## 指示書の前提を2つ直した

⚠️ **どちらも「そのとおり実装していたら壊れていた」もの。**

**1つめ: 展開順は「リストの逆順」ではなかった。** 指示書は
「`unexp_boards.pop()` は末尾から取るので展開順はリストの逆順」としていたが、
`unexp_boards` は list ではなく **`set`** だった（書き出しが `set(...)` なので
`pickle.load` が返すのも `set`）。CPython の `set.pop()` は `finger` から表を
前方に走査するので、繰り返し pop した順は集合の反復順そのものになる。

| 手元で確かめたこと（n = 5 / 1,000 / 200,000） | |
|---|---|
| `pop` を繰り返した順 == `list(set)` | **True** |
| `pop` を繰り返した順 == 挿入リストの逆順 | **False** |
| `list(array("Q", set))` == `pop` の順 | **True** |

指示書どおり末尾から走査していたら順序が反転し、採番順も バイト一致も壊れていた。
C は**前から後ろへ**回している。

**2つめ: コンテナ型が変わっても `dat/` のバイト列は変わらない。** 指示書は
「list → `array("Q")` で pickle されるオブジェクトの型が変わるので `dat/` も変わる」
としていたが、`dat/` に出るものはすべて `set(...)` を通っている。
`set(list)` と `set(array("Q"))` は同じ挿入順ならバイト一致する
（n = 10 / 1,000 / 100,000 で確認）。だから指紋ではなく**最初からバイト比較を狙えた**。
