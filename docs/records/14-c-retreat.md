## 記録 #13 の不具合の型を作らないようにした

記録 #13 は「呼び出しをまたいで残る件数を、空入力の早期 `return` がリセットし損ねる」
不具合を作った。今回は **C 側に static を1つも置いていない**。

| | |
|---|---|
| カーソルの持ち主 | Python 1か所。C には書き始めの位置と空き容量を渡し、書いた数だけを返させる |
| `out[0] = 0` の位置 | `out` の NULL 検査の直後。どの早期 `return` よりも前 |
| 境界検査 | `q >= n_all`（`pred_off` の外）と `p >= n_uk`（`cnt` の外） |
| 異常時 | `-1` 引数不正 / `-2` 容量不足 / `-3` 範囲違反 / `-4` カウンタ不整合。Python は 0 以外をすべて `raise` |

⚠️ **`-4` は Python 版が `bytearray` への代入で `ValueError` になっていたところ。**
`cnt[p]` が 0 のときに減らすと 255 に回り、その局面は二度と確定しなくなる。
黙って回さず、同じ場所で落とす。

## テストが自分のコメントに2回引っかかった

「早期 `return` より前にリセットを置く」ことを検査する行は、**その説明文に
`return` という語を含んでいる**。`docs/review-checklist.md` の
「規約を書いた文が、その規約で落ちる」そのもので、C のコメントを落としてから
見るようにした。

⚠️ **`out` の NULL 検査だけは書き込みより前に要る**ので、そこを唯一の例外として
明示した（例外を作らないと、書けないポインタに書く検査になる）。
