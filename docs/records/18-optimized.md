# 記録 #18 で分かったこと

**`Makefile` の `gcc` 行に `-O2` を足した。それだけ。**

記録 #17 までの `Makefile` は `gcc animal_shogi.c -o animal_shogi.so -Wall -fPIC -shared`
で、**`-O` が1つも付いていない＝`-O0`**。18記録ぶん、ローカル変数を毎回スタックに
書き戻すビルドで走ってきた。梯子1段目は「`-O2` にする」ではなく
**「`-O0` をやめる」**だった。

**完走 0:07:15 → 0:05:25（73.86× → 98.83×）。−109.88 秒。**

⚠️ **このリポジトリで `Makefile` が前の版と違う最初の実装。** `baseline/` と
`impl/01`〜`17` の18個は全部同じハッシュで、既存テスト7本が「`Makefile` は
バイト同一」を固定していた。うち5本（`test_impl_08/11/12/13/14/15`）は
**「`-O2` は別の試行で1変数として測る」とこの記録を名指しで予告していた**。

## 段は門番で決めた — 規則を測る前に固定して

5腕（`o0` / `o1` / `o2` / `o3` / `o2n`）を4本ずつ、**全探索合計**で比べた
（[`gate_18_opt`](../../experiments/gate_18_opt/)）。完走タイムで判定しなかったのは、
その雑音がほぼ全部後退解析から来ているため（4本ずつの95%半幅が全探索合計
1.4〜5.7 秒に対し完走タイム 28 秒）。

> **`-O3` と `-O2` の差の95%区間が 0 を含むなら `-O2` を採る。**
> 理由は速さではなく、コードサイズを増やさない慣例線だから。

| 腕 | 全探索合計 | `o0` との差（95%区間） |
|---|---|---|
| `o0`（フラグなし） | 185.13（sd 3.42） | — |
| `o1` | 132.40（sd 1.09） | −52.73（−57.94 … −47.52） |
| **`o2`** | **128.63（sd 1.54）** | **−56.50（−61.63 … −51.37）** |
| `o3` | 128.87（sd 5.25） | −56.26（−64.24 … −48.29） |
| `o2n`（`-O2 -fno-semantic-interposition`） | 126.65（sd 3.89） | −58.47（−64.84 … −52.11） |

`o3 − o2` は **+0.24（区間 −7.79 … +8.26）**で 0 を含んだ。規則どおり **`-O2`**。

⚠️ **`-Ofast` は最初から外してある。** 危険だからではなく**得るものがゼロだから**。
`.c`/`.h` に浮動小数点が1つも無い（`float`/`double`/`<math.h>` すべて 0 件）ので
`-ffast-math` は何もしない。`-march=native` は別のレバーなので混ぜていない。

## ④を外した — 合計で見るか段で見るか

`o2n`（`-fno-semantic-interposition`）は**全探索合計では区間が 0 をまたいだ**が、
**F1 単独では −3.75（区間 −4.91 … −2.58）で 0 をまたがない**。

事前登録にどちらで見るかを書いていなかった。判定に使う量は §3-1 で全探索合計と
決めてあったので、**それに従って ❌ とする**。⚠️ ただし外した理由は「効かなかった」
ではなく「**F2 と F5 の雑音に埋もれた**」。この2段は腕にかかわらず時々跳ね
（`o0` の1本で F2 16.25 / F5 15.85）、全探索合計の sd を 3.4〜5.3 秒に押し上げる。
F1 単独なら sd は 0.5〜1.3 秒。

機構のほうは確かめてある。`-fPIC -shared` では同じ `.so` の中の呼び出しも
インライン展開されない（実行時に差し替えられうるため）。`objdump -d` で数えると
`normalBoard` への `call` は `-O2` で **3 箇所**、`-O2 -fno-semantic-interposition` で
**0 箇所**。`nextBoardInvNormal` → `normalBoard` は**深さ2 で約12〜13億回**通る。
これを `#19` の事前登録にする。

## ⑥を半分外した — `-O` が効く関数は P2 にも居た

「後退解析は DRAM レイテンシ律速なので、下がり幅の割合は全探索より小さいはず」と
登録していた。**まとめて見れば当たっている**が、**P2 単独は外した**。

| 段 | `#17` | `#18` | 差 |
|---|---|---|---|
| P0 読み込み | 3 | 3 | 0 |
| P1 索引 | 20 | 14 | −6 |
| **P2 後続生成** | **96** | **62** | **−34（−35.4%）** |
| P4 前任リスト | 70 | 63 | −7 |
| 174段ループ | 36 | 28 | −8 |

`-O` が確実に効くのは `nextBoardInvNormal` / `invBoard` / `normalBoard` の
純ビット演算で、**それは F1 だけでなく P2 の中にも居る**。

```
F1: expandRound → nextBoardSeenNormal → nextBoardInvNormal   約 2.47 億回
P2: buildSuccRange → nextBoardIndexNormal → nextBoardInvNormal  約 9,949 万回
```

事前の C の監査は**この経路を挙げていた**のに、P2 に計算がどれだけ乗っているかを
重みとして見ていなかった。⚠️ **「メモリ律速だから `-O` は効かない」は段の名前では
決まらない。中で何が呼ばれているかで決まる。**

## 検証 — バイト一致の鎖が戻った

| | |
|---|---|
| オラクル | 174行すべて一致（[`verify.txt`](../../results/18_optimized/verify.txt)） |
| **バイト比較** | **`#17` の `dat/` と全213ファイルが一致**（`diff -rq` 終了コード 0、md5 一覧の sha256 も一致。[`bytecompare.txt`](../../results/18_optimized/bytecompare.txt)） |
| 指紋 | `oracle/fingerprint.tsv` の176項目と一致 |
| サイズ | 213 ファイル / 1,974,425,336 バイト / ÷ 8 = 246,803,167（端数 0） |

⚠️ **`-O2` は `-fstrict-aliasing` を有効にする。** 未定義動作があればここで初めて
答えが変わりうるので、この記録ではバイト比較がいちばん強い検査になる。
事前に C を監査して、型のすり替えも `union` も型パンニングも無いことを確かめてあった
（ポインタキャストは `aligned_alloc` / `realloc` の戻り値4件だけ）。門番でも
**5腕の成果物がバイト同一**であることを別に見ている。

`#16` で形式を変えて切れ、`#17` で `set(...)` を外して切れたままだった鎖が、
ここで戻った。`-O` は「どう計算するか」を変えて「何を計算するか」は変えない。

## 等価性検査は `-O2` を見ていない

⚠️ `tests/conftest.py` の `build_library()` は自前の `gcc -Wall -fPIC -shared`
（＝`-O0`）でビルドするので、**等価性検査は `Makefile` を1行も通らない**。
`#17` と `#18` はその中では同一のビルドになる。

そこで `tests/test_impl_18_optimized.py` に「`make animal_shogi.so` が実際に通り、
警告を1つも出さず、`-O0` ビルドとはバイトが違うこと」を見る検査を置いた。
**この記録のレバーを実際に走らせているテストはそれだけ。**

## 警告はゼロだった

18記録ぶん `-O0` で走ってきたので、最適化を有効にしないと出ない警告
（`-Wmaybe-uninitialized` など）が初めて露出する可能性があった。
**5腕とも `-Wall -Wextra` で警告ゼロ**（[`logs/warnings.txt`](../../experiments/gate_18_opt/logs/warnings.txt)）。

事前に1箇所を疑っていた。`animal_shogi.c:95` の `int *moves;` は `default:` 経路
（`koma ∈ {1,2,3,5}`、実際に到達する）で未設定のまま抜ける。直後の
`if (!moves_num) continue;` で読まれないので挙動は正しいが、値域解析が
`moves` と `moves_num` の相関を追えないと警告が出る。GCC 13.3.0 は追えていた。
⚠️ **追えない処理系では出る**ので、CLAUDE.md の「次の実装で必ず直すもの」に積んだ。
