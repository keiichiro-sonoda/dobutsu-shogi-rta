# 記録 #19 で分かったこと

**億単位のループで Python に残っていた最後の2か所を C へ移し、後退解析に境界を置いた。**

後退解析は**連番**で動くが `dat/` に書くのは**パック値**で、その翻訳がリスト内包に
残っていた。記録 #16（読む側）・#17（書く側）とまったく同じ形の3回目。

| | 回数 | していたこと |
|---|---|---|
| ① 174段ループ `[packed[i] for i in found]` | **96,802,868** | `PyLong` を2個（添字と盤面値）起こして `list` に積む |
| ② 引き分けの抽出 `[packed[i] for i in range(n_uk) if dtm[i] == 255]` | **99,485,568** 走査して **2,682,700** 採用 | 同上 |

**完走 0:05:25 → 0:05:03（98.83× → 105.71×）。−21.17 秒（−6.5%）。初めて100倍を超えた。**

内訳は全探索 128.68 → 127.81 秒（**−0.88**。全探索側で変えたのは計装の `getrusage` だけ）、
後退解析 196.44 → **176.14** 秒（−20.29）。

## ②は #18 まで一度も測られていなかった

`writeUnknownChunks` のタイマーは**関数の中**で始まるのに、リスト内包は
**引数なので呼ぶ前に終わっている**。9,948 万回の走査は計測窓の外にいた。

```
未知盤面の書き出し時間：00時間00分00秒     ← 嘘ではない。書き出し自体は 0.18 秒
```

⚠️ **この記録はレバーと計装が同じ実装に入る。** だから新しい区間
`R_loop`→`R_draw` には「前の値」が存在しない。門番の `old` 腕を
**「`impl/18` ＋ 計装だけ」**にして、その区間の before / after を両方出した
（[`gate_19_c_gather`](../../experiments/gate_19_c_gather/)）。

## `gatherDraws` は2周する

出力の長さが事前に分からない。`#13`・`#15` は「容量不足で止まって呼び直す」形を
採ったが、**ここは2周すれば寸法が分かる**。1周目は `out` に NULL を渡して数え、
呼び出し側がちょうどの長さを確保してから2周目で詰める。

2周しても 2.0 億バイトの直線走査で、門番では**2周こみで 0.15 秒**。
伸びるバッファも再開の仕組みも持ち込む理由にならない。

`gatherPacked` のほうは出力の長さが `n` ちょうどなので、1周で済む。
どちらも `found` の値が `n_all` 以上なら `-3` で落とす（黙って別の局面を
書き出さないため。`#14` の `retreatStep` と同じ理由）。

## 見送った2件

`CLAUDE.md` の「次の実装で必ず直すもの」は当てなかった。理由は別々。

- **`nextBoardInvNormal` の `int *moves` が未初期化** — `moves = NULL;` の1行で
  消えるが、この関数は `expandRound` → `nextBoardSeenNormal` から**全探索の経路でも
  呼ばれる**。この記録が全探索の経路で変えたのは `_profMark` の `getrusage` だけで
  （出力は変えない）、C に足した行は全探索では実行されない（予測⑤の前提）。
  `moves = NULL;` を混ぜると、全探索側で動いたものが2つになる。
- **`updateUKFile()` の分割が2つまで** — `CLAUDE.md` が
  「直すとチャンクの切れ目が動くので、レバーと同じ扱いで1試行に1つ」と
  名指しで別の試行に回している。

2件とも `tests/test_impl_19_c_gather.py` が「まだ残っていること」を固定した。
直したら、その固定と `CLAUDE.md` の項目を一緒に畳むこと。

- **門番の差（−21.77）を本走の差（−20.29）と引き算した値。**

- **計装の間接的な影響。** 直接コストは 0.86 ミリ秒と測ったが、行が増えたことでの
