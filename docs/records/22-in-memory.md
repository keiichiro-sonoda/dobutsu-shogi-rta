# 記録 #22 で分かったこと

**全探索が書いて、同じプロセスがあとで読み戻して消していたファイルをやめ、全探索から後退解析までを
メモリで受け渡した。** 改善の梯子の3段目。

**完走 0:03:33 → 0:03:09（150.22× → 169.64×）。−24.49 秒（−11.4%）。**
内訳は全探索 109.49 → 83.37 秒（−26.12）、後退解析 104.41 → 106.04 秒（+1.63。下の「本走」）。
`dat/` は #21 と全213ファイルでバイト一致した。

| ファイル | #21 まで | #22 |
|---|---|---|
| `unexplored###.bin`（待ち行列） | F5 で末尾のファイルを読み直して継ぎ足し、次のラウンドの F0 で読んで消す | メモリの待ち行列 |
| `unknown###.bin`（全探索の未知） | F2 で末尾のファイルを読み直して継ぎ足し、P0 で読んで消す | メモリの配列 `uk_all` |
| `win001te_*` / `lose000te_*` | F6 で書き（成果物）、P0 で読み戻す | F6 はそのまま書く。P0 は読み戻さない |

#21 の全探索が作業ファイルに書いた量は **4.91 GiB**（[`io_volume.py`](../../experiments/gate_22_in_memory/io_volume.py) が
#21 の `forward.tsv` の件数からファイルの状態をなぞって数えた）。本走の `time.txt` の `File system outputs` は
14,157,544 → 3,857,640 ブロック（512 バイト）で、差の 10,299,904 ブロックはちょうど 4.91 GiB だった。

## 並びを変えないための3つ

1. **待ち行列は先に入れたものから取り出す。** 何件ずつ取り出しても展開の順は変わらないので、
   未知の並び、1手勝ち・0手負けの並びも変わらない
2. **P0 の詰め方（後退解析の採番順）を再現する。** #21 の `unknown###.bin` は、未知の並び U を先頭から
   500万ちょうどで区切ったもの（1ラウンドの未知は500万以下なので、`updateUKFile()` の3個以上の分割は一度も
   起きていない）で、P0 は末尾のファイルから詰めていた。#22 は U を同じく区切り、末尾の塊から詰める。
   ラウンドの区切りには頼らない
3. **初期局面を最初に発見済み表へ入れる。** `expandRound()` は入力の局面を表に入れない。#21 までは
   1ラウンド目のあとの `buildSeenBoards()` が `unknown000.bin`（中身は初期局面1つ）を読むのが唯一の経路で、
   ファイルごと消える。入れ忘れると、4手で戻ってきた初期局面を初見として積む

途中の `dat/` から再開する経路（未探索ファイル探し、「探索済み」、`buildSeenBoards()`）と `updateUKFile()` は消した。
再開はレギュレーション違反なので、入口で `dat/` が空でなければ止める。F1 の文は #21 とバイト同一。
F0・F2・F5・S の区間は、中身がほぼ空になっても `forward.tsv` の列を揃えるために残した。

## 門番 — 待ち行列の区切り方で2腕

[`gate_22_in_memory`](../../experiments/gate_22_in_memory/)。単位は完走（後退解析がファイルを読まなくなったので、
全探索の出力から後退解析だけを回す門番では P0 の受け渡しを通せない）。3腕 × 6本、`numactl` で片ノードに固定。
各腕は各位置に2回ずつ、ブロックの中で隣り合う前後の組も2回ずつ来る。比較は3本で、p 値と区間は多重比較未補正。

| 腕 | 待ち行列 | ラウンド数 |
|---|---|---|
| `old` | `impl/21_hugepages` のまま（ファイル） | 74 |
| `chunk`（A） | メモリ。500万件ずつ（`min(5,000,000, 待ち行列の長さ)`） | 74（#21 と同じ） |
| `whole`（B） | メモリ。区切らない（1ラウンドが幅優先の1層） | 40 |

A と B の差は `queuePush()` の1関数だけ。判定の量は **J ＝ `forward_total` ＋ `P0`**（3腕でコードが違うのは
ここに入る段だけ）。**B − A の区間が 0 をまたがずに上のときだけ A を採り、それ以外は B を採る**と、回す前に決めていた。

| 量 | `old` | `chunk` | `whole` | `whole − chunk`（95% 区間） |
|---|---|---|---|---|
| **J** | 109.05 | 83.38 | 85.86 | **+2.48（+2.06 … +2.91）** |
| F0 ＋ F2 ＋ F5 | 26.44 | 2.17 | 0.56 | −1.61 |
| P0 | 3.98 | 1.41 | 1.41 | +0.00（−0.01 … +0.02） |

| F6 | 1.92 | 2.47 | 3.15 | +0.67（+0.64 … +0.71） |

**B は 2.48 秒遅く、区間が 0 をまたがなかったので A を採った。** `chunk − old` は J で −25.67 秒
（区間 −27.57 … −23.76）。18本とも #21 本走とバイト一致し、`chunk` は6本とも件数の列が #21 の
`forward.tsv` と全74ラウンド一致した。表は [`judge.py`](../../experiments/gate_22_in_memory/judge.py) の出力の抜き出し。

### B が遅かったのは F1 と F6 のカーネル時間

B は塊へ写さないぶん F0 ＋ F2 ＋ F5 が 1.61 秒軽いが、F1 が +3.43 秒（うちカーネル時間 +2.77、
ユーザー時間 +0.66）、F6 が +0.67 秒（うちカーネル時間 +0.55）重かった。B は minor fault が A より
113.83 万回多く、マシン全体の `numa_local`（ノード内で割り当てたページ）も約 118 万ページ多い。
**新しいページを多く触っている。** B の1ラウンドは最大 30,196,273 件で、展開の作業用配列
（入力の写しと、勝ち・負け・未知の受け皿）が1本 240 MB になる。**機序は分けていない。**

### 500万の返済は、3段のうち1段目で止まった

`BOARD_NUM_MAX = 5000000` は 2021年のメモリ 2 GB に合わせた数で、3か所に効いている。

| 段 | 何に効くか | #22 |
|---|---|---|
| 1 | 待ち行列の区切り（1ラウンドで展開する数） | **ファイルはやめたが、区切りは残した**（区切らない B のほうが 2.48 秒遅かった） |
| 2 | P0 の詰め方（後退解析の採番順） | 変えない。変えると採番順が動く。別のレバーで、後退解析の門番で測る |
| 3 | 成果物の区切り（`BOARD_NUM_MAX` ずつのファイル） | 変えない。保存形式の変更で、バイト比較の鎖が切れる |

1段目は「ファイルをやめる」までは返済できたが、区切りそのものは門番でむしろ得だった。
**500万は2021年の名残だが、いまも区切ること自体に意味がある**（大きさを変えたらどうなるかは測っていない）。
