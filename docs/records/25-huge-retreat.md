## 174段ループは先読みと待ちを取り合った

**`loop174` は −1.61 秒で、lever_scan_2 の単独（先読み無し）の −7.91 秒の約 2 割にとどまった。**
lever_scan_2 で、3段の先読みの上に重ねたとき（`all − pf3`）の −1.54 秒とほぼ同じ。

| | 先読み無しに足す | 先読みの上に足す |
|---|---|---|
| lever_scan_2（6本、多重比較未補正） | −7.91（`hugeR − base`） | −1.54（`all − pf3`） |
| この門番 | — | **−1.61**（`new − old`。`old` は #23 の2段の先読み入り） |

174段ループの待ちは、`pred_off[q]` → `pred[e]` と前の読みで次の番地が決まる DRAM 読みで、番地の翻訳と中身の取り寄せの
両方を待っていた。#23 の先読みは両方を前倒しで重ねて隠す。巨大ページは翻訳を軽くする。先に先読みで隠してあると、
翻訳を軽くしても縮む待ちが残っていない。下がったのはユーザー時間（−1.62）で、カーネル時間は +0.02 秒
（+0.003 … +0.036）とわずかに増えた。

**予測でいちばん確かめたかったのはここで、単独の −7.91 がそのまま出れば読みが外れていた。** 出なかった。
P4 は先読みが `P4_scatter` にしか無く、lever_scan_2 でも単独（−3.48）と重ねたとき（−3.47）がほぼ同じだったので、
取り合いは174段ループに特有だった。

## 計装と片付け

**計装の費用**: 後退解析の配列の巨大ページを読む `smaps_rollup` は、門番で `old` 45.7 ミリ秒・`new` 20.4 ミリ秒、本走で
20.5 ミリ秒（`smaps_loop_sec`）。`R_uk` のあとなので、どの区間にも入らないが、完走の壁時計には入る。
本走の `anonhuge_index_kB`（P2 の終わりに読む）は 8,388,608 → 8,486,912 kB になった。差の 98,304 kB は `cnt` のぶんで、
`cnt` は P2 の間に確保されるので、索引と一緒に読まれる。索引そのものの巨大ページは変わっていない。

**受け皿の片付け**: 全体のピーク RSS（P2）は、#24 本走の 14,655,768 kB から 14,517,116 kB（−138,652 kB）に戻った。

**F6 が 0.6 秒短くなった（`hugeR` とは関係がない）**: 門番の F6 は両腕とも 1.82 秒で、#24 の門番（両腕 2.41 秒）より短かった。
`old` も `new` も同じなので `hugeR` の効果ではなく、計装か片付けのどちらかが入ったことによる（片付けは F6 のあとなので、
時間の上では計装のほう）。F6 の minor fault は 283,214 回で、lever_scan_2 の `reuse` 腕（計装入り）と1回も違わない。
#24 の門番で「lever_scan_2 で下がっていた F6 が再現しない」としたのは、この計装の有無の違いだった可能性がある。機序は分けていない。
