## ランク

定義域は `normalBoard` で正規化した盤面（ライオンは盤上に1頭ずつ）。設計の段階で本人と方向を合わせ、鏡像をまとめる形にした。

1. **ライオンの組**: 手番側（4）と相手（12）の置き方 12 × 11 = 132 通りを、左右の鏡像どうしでまとめて **72 組**にする。
   2頭とも中央の列にある 12 通りは鏡像が自分自身なのでそのまま、残り 120 通りは 60 対になる。まとめた側は盤を左右反転してから数える
   （同じ局面の類なので単射のまま）。反転するかどうかは分岐を使わずに選ぶ
2. **残り 10 マス**: ライオンの2マスを抜いて詰め、5マスずつに分ける。各マスは 9 通り（空き、きりん・ぞう・ひよこ・にわとり × 持ち主）なので、
   5マスを 9 進数にして前計算の表（59,049 項目）を引き、「駒の数の組（きりん・ぞう・ひよこ各 0〜2）」と「その組の中での順位」を得る。
   前後の組を合わせ、種類ごとに 2 以下になる組み合わせだけを数える（27 × 27 の表）
3. **持ち駒**: 種類ごとに盤上の数 n が決まれば持ち駒の合計は 2 − n なので、下位の持ち駒（bit 48〜53）の数だけを基数 3 − n で数える

| | |
|---|---|
| ライオンの組1つあたり | 11,878,227（きりん・ぞう・ひよこ各2枚を、盤上の10マスに置くか持ち駒にする置き方） |
| 値域 | 72 × 11,878,227 = **855,232,344**（到達局面 246,803,167 の **3.47 倍**） |
| 前計算の表 | 約 0.25 MB。`seenInit` の最初の1回だけ作る |

**値域と前計算の表は、駒の数と盤の形（ルール）だけから数える。** 到達局面の数や解析の結果は使わない（#11 で発見済み表の初期サイズに
既知の総数を使わなかったのと同じ理由）。ライオンの組を 132 通りのまま数えると、全体は 132 × 11,878,227 = 1,567,925,964 になる。

**#28 の成果物の全 246,803,167 局面で単射**（不正な盤 0、値域の外 0、重なり 0）であることを、門番を回す前に確かめた
（[`rank_check.c`](../../experiments/gate_30_rank_seen/rank_check.c)、[`rank_check.txt`](../../experiments/gate_30_rank_seen/logs/rank_check.txt)。
`impl/30` の `animal_shogi.c` をそのまま取り込む）。`tests/test_impl_30_rank_seen.py` が、C の前計算の表のランクが素朴な実装
（Python で同じ定義を数え上げる）と一致すること（ライオンの組 132 通りすべてを含む乱数の盤）、値域が 72 × 11,878,227 になること、
正規化した盤面どうしで単射なこと、打ち切って回した成果物が #28 とバイト一致すること（それぞれの `Makefile` の `.so` で）を固定している。

### 止める条件3に掛かり、原因を調べてから本走した

動かないはずの段のうち、**F6 が +0.61 秒、P2 が −0.24 秒**で、回す前に決めた「区間が 0 をまたがず 0.2 秒以上動いたら本走の前に原因を調べる」に
掛かった。F5 も +0.16 秒（しきい値の下）。

F6 は、minor fault が 283,214 → 568,464 回（2倍）になり、カーネル時間が +0.45 秒だった。F5・F1 でも約 6.7 万回ずつ増えた（予測は「数千回減る」で外れ）。
原因は **glibc の malloc の mmap のしきい値**だった。

- malloc は、しきい値より小さい確保をヒープ（手元に残して使い回す領域）から、大きい確保を `mmap`（OS から毎回新しくもらい、`free` で返す）で行う。
  しきい値の既定は 128 KiB で、mmap で確保した塊を `free` すると、その大きさ（最大 32 MiB）まで自動で引き上げられる
- `old` は発見済み表を 8 MiB から倍々に作り直すたびに古い表を `free` していたので、しきい値が 32 MiB まで上がり、F5・F6 の数 MiB〜数十 MiB の
  配列がヒープの使い回しで済んでいた（ページの用意がほとんど要らない）
- `new` はビット表を `free` しないので、しきい値が既定のままで、F5・F6 の配列が毎回 `mmap` され、ページの用意をやり直していた

しきい値を 32 MiB に固定して（`GLIBC_TUNABLES`。固定すると引き上げの仕組みも止まる）2腕を1本ずつ回すと、F5・F6 は時間もフォルトの数も2腕で
そろい（F6 のフォルトは同じ 863,158 回）、F1 の差（約 −12 秒）は残った
（[`diag_mmap.sh`](../../experiments/gate_30_rank_seen/diag_mmap.sh)、[`logs/diag/`](../../experiments/gate_30_rank_seen/logs/diag/)。判定には使わない診断）。
**F6 の +0.6 秒はランクの効果ではなく、`old` が作り直しの `free` から偶然受けていた恩恵が無くなったもの。** この結果を本人に報告し、本走に進んだ。
P2 の −0.24 秒（速くなる側、区間の端がほぼ 0）の原因は分けていない。
