### q だけから戻す形と、辺の本数を保つ2つの規則

鏡像の q から戻した候補は、q から戻した候補の鏡像と1対1に対応する（移動量の表・盤の端・「戻した先から相手のライオンに利く戻し方は作らない」の判定がどれも左右対称）。
だから q だけから戻して、鏡像の側の分を正規化で代わりに出せる。後退解析の「残りの数」を辺1本につき1つ減らす数え方と合わせるため、次の2つを守る。

1. **q が左右対称でない**: 戻した候補 c ごとに正規形 N(c) を出す。**c が左右対称なら2回出す**（p が対称だと、p → q と p → 鏡像の q は別の手なのに、q からは片方しか見えない）。
   書き方は `out[n] = out[n+1] = N(c); n += 1 + (c が対称)`
2. **q が左右対称**: 今までと同じく、c が正規形のものだけを残す（正規化して出すと、手と鏡像の手から同じ p が2回出て多く数えてしまう）

この2つで、q ごとの候補の**多重集合**は #36 と同じになる。`mirror1_keep` が到達可能な全 246,803,167 局面で確かめた（不一致 0）。
`unmoveEmit`・`unmoveCaptures`・`unmovePiece`・`unmoveRaw` に「正規化して出すか」の引数を足し、`unmoveCandidates` が q の対称で2通りに呼ぶ（定数の引数で、インライン展開で畳まれる）。

### 並べ直しを入れなかった理由

並びを #36 と同じに保つ版（`mirror1_keep`。鏡像の q から出ていた分を、鏡像の q の走査順の鍵と一緒に溜めて最後に並べ直す）も作って測った。
生成器だけのベンチで、`mirror1` の得 −318.1 cycles / 局面に対して並べ直しの費用は ＋104.5（33%）、完走の比較では `mirror1` −9.47 秒・`mirror1_keep` −6.08 秒で、
**並べ直しが得の約3分の1を食った**。並べ直して守れるのは、答えに入らないファイルの中の並びだけ（答えは手数ごとの集合で完全に確かめられる）。だから入れなかった。
