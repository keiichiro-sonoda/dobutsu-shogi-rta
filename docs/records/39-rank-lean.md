**完走 0:01:25 → 0:01:21（374.92× → 391.89×）。−3.71 秒。** 内訳は全探索 49.65 → 47.70 秒（F1 43.97 → 42.00 秒）、後退解析（完走 − 全探索）36.05 → 34.29 秒。

## 何を変えたか

`impl/38_precheck` に [`experiments/rank_fast/patches/lean.patch`](../../experiments/rank_fast/patches/lean.patch) を当てただけ。変わったのは `rankOf` と、表を作る
`rankTablesBuild`（表 `g_rank_keep[144]` と `g_rank_hpart[27][64]` を足す）だけで、`.py`・`Makefile`・`hot_layout.ld`・ヘッダ・既存の表の中身・`rankFindKoma`・
`rankSqueeze`（どちらもほかで使うので残した）・生成器・逆向きの生成器・呼び出し側は #38 とバイト同一（[`tests/test_impl_39_rank_lean.py`](../../tests/test_impl_39_rank_lean.py) が固定している）。
関数の記号は #38 と同じ。`CLAUDE.md` の「次の実装で必ず直すもの」は空だった。

`rankOf` は、盤の 12 マス（1マス4ビット）と持ち駒（48 ビット目から上）から、ライオンの組・前半と後半の5マスずつの組と順位・持ち駒を数えて番号を出す。3か所を書き換えた。

### 1. ライオンの2マスを1回で探す

#38 は `rankFindKoma` を2回（`LION1` と `LION2`）呼び、それぞれ盤とライオンの値を XOR して 0 になるマスを探していた。
駒の値は `CHICK1` 1・`GIRAFFE1` 2・`ELEPHANT1` 3・`LION1` 4・`CHICKEN1` 5 と、上のビット（持ち主）を立てた 9〜13 で、**下位3ビットが `100` になるのはライオン（4 と 12）だけ**。
そこで `z = (b >> 2) & ~(b >> 1) & ~b & 0x111111111111` で、両方のライオンのマスの最下位ビットに印を1回で立て、`z2 = z & (b >> 3)`（持ち主のビットが立っている側 ＝ `LION2`）と
`z ^ z2`（`LION1`）に分けて、それぞれ `tzcnt` する。正しい盤ではライオンが1頭ずつ盤上にいるので、どちらも 0 にならない（`rankValid` が見ている）。値は `rankFindKoma` と同じマス。

### 2. 2マスを抜いて詰めるのを `pext` 1回にする

#38 は反転したあとの盤から、ライオンの2マス（`hi` と `lo`）を `rankSqueeze` で1つずつ抜き、上の組を4ビットずつ下へ詰めていた（シフトとマスクの鎖が2回）。
**`pext`（BMI2）は「マスクの1のビットの位置にある値を拾って、下から詰めて並べる」命令**なので、48 ビットのうち2マスの4ビットずつを 0 にしたマスクで1回 `pext` すれば、
`rankSqueeze` を2回当てたのと同じ値になる（`hi` を先に抜いても、残ったマスの並びは変わらない）。マスクはライオンの組ごとに決まるので、`g_rank_lion` の `hi` / `lo` から
表 `g_rank_keep[144]`（1,152 バイト）を表を作るときに1回作る。

### 3. 持ち駒の部分を表1回の読みにする

番号の持ち駒の部分は `(h & 3) + (3 − ひよこ) × (((h >> 2) & 3) + (3 − きりん) × ((h >> 4) & 3))` で、`3 − ひよこ`・`3 − きりん` は盤上の駒の組（種類ごとの枚数）で決まる。
#38 はそれを前後の組の対 `g_rank_hand[s0][s1]` から読んで掛けていた。組は3進3桁（きりん × 9 ＋ ぞう × 3 ＋ ひよこ）で、**正しい盤では種類ごとに盤上 2 枚以下なので、
前半と後半の組の和 `s0 + s1` は桁が上がらず、合わせた組そのものになる**。そこで、合わせた組 × 持ち駒の下位6ビットの表 `g_rank_hpart[27][64]`（1,728 バイト）を1回引く。

- 1呼び出しあたりの命令は 137 → 105（`rank_fast` の `rankOf` だけのベンチ）。表の読みの数は 15 回のまま（`g_rank_lion` の `hi` / `lo` の2回が新しい2つの表に替わる）
- **#39 から BMI2 に頼る。** 計測機（Broadwell）は持っていて、`Makefile` の `-march=native` で使われる（[`march.txt`](../../results/39_rank_lean/march.txt) に `__BMI2__`）。
  BMI2 の無い CPU ではこの `.so` は動かない。`pext` は `.so` に7個（`nextBoardSeenNormal`・`unmoveStep`・`unmoveDraws` 2・`rankBoard`・`seenInsert`・`seenContains`）

### `rank_fast` で分かった `rankOf` の重さ

`rank_fast` の段1で #38 の `rankOf` を測ると、F1 14.33 秒・`U_loop` 9.35 秒・`U_draw` 1.51 秒（`perf record` の標本の割合 × 段の秒。全部ただになったときの上限）。
本物の 1呼び出しあたり（F1 49.8・`U_loop` 53.7 cycles）を、`rankOf` だけのベンチで3つに分けると、**計算（表が L1 にある独立な呼び出し、47.4 cycles）が 92%**、
L2 の待ち（`g_rank_half` 236 KB の外れ）5%、文脈で重ねきれない分 3%。だから「命令を減らす」を1本だけ作った。
