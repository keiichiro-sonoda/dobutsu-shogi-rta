# 実験: 48要素バッファの毎回確保をやめると、どれだけ効くか

⚠️ **これは記録試行ではない。** タイムを `results/` や README の記録表に載せない。
入力を固定して後退解析だけを走らせた比較であり、レギュレーションの
「空の `dat/` から完走」を満たしていない。

## なぜ測ったか

記録 #8（`impl/08_c_index`）は「パック値 → 連番」の照合をC側へ移したが、
**同時にもう1つの効果を取り込んでしまう**。#7 までの後退解析は

```python
def nextBoardInvNormalWrap(b) -> tuple:
    nba = c_uint64_array48()          # ← 未知盤面ごとに確保. 99,485,568 回
    nbn = nextBoardInvNormal(b, nba)
```

と、呼び出しのたびに 48 要素の ctypes 配列を作っていた。#8 はバッファを
ループの外で1回だけ確保するので、この確保も一緒に消える。
**梯子ではこれを別のレバーとして数えていた**ので、#8 の改善のうち
どれだけがこちらのぶんなのかを分けておきたかった。

## 何を変えたか

`impl/07_batch_forward_write/animal_shogi.py` に対して**1行だけ**。
後退解析専用の使い回しラッパーを足し、`buildSuccessors` がそれを呼ぶ。

```python
_retreat_nba = c_uint64_array48()          # 追加

def nextBoardInvNormalWrapReuse(b) -> tuple:
    nbn = nextBoardInvNormal(b, _retreat_nba)
    ...

-        nbn, nbl = nextBoardInvNormalWrap(packed[i])
+        nbn, nbl = nextBoardInvNormalWrapReuse(packed[i])
```

辞書はそのまま、呼び出しの形も PyLong の生成も同じ。
**違うのは `c_uint64_array48()` を 99,485,568 回呼ばないことだけ。**
前向き探索が使う `nextBoardInvNormalWrap` には触っていない（この実験では走らせない）。

## どう測ったか

```bash
experiments/ffi_buffer_reuse/run.sh > exp_buf.out 2>&1
```

- 入力は `runs/g1_07_batch_forward_write/dat`（全探索が終わった直後の状態、2.1 GB）。
  ⚠️ **git 管理外。** 無ければ完走した `dat/` から `tools/rebuild_forward_fixture.py` で作り直す
- C は `baseline/` のまま（`-O0`）。CPython 3.12 / 同一マシン。他の計算は流していない
- **`tools/verify_log.py` でオラクル174行を確認**（[`logs/console.log`](logs/console.log)）

## 結果（秒）

| | P0 | P1 | **P2** | P4 | 174段 | 残差 | 合計 | ピーク RSS |
|---|---|---|---|---|---|---|---|---|
| #6（記録） | 93 | 161 | 969 | 554 | 265 | — | 2,087 | — |
| #7（記録） | 95 | 167 | **1,035** | 546 | 264 | 49 | 2,156 | 30.65 GiB |
| **本実験** | 96 | 180 | **1,033** | 550 | 264 | 50 | **2,172.8** | 30.61 GiB |
| 参考: #8 | 96 | 20 | 223 | 548 | 262 | 36 | 1,184.9 | 13.84 GiB |

## 結論：分離できなかった

**P2 は 1,035 → 1,033 秒（−2 秒）。** 合計も 2,156 → 2,172.8 秒（+16.8 秒）で、
どちらも同一コードの振れ幅の内側にある。

⚠️ **これは「効果が無い」ことを示したのではない。** 各1本なので、
**この本数では見えなかった**というだけ。同じコードを繰り返し測ったときの幅は

| 段 | 観測 | 幅 |
|---|---|---|
| P1（辞書構築） | 161 / 167 / 180 | **11.8%（約 19 秒）** |
| P2（後続生成） | 969 / 1,035 / 1,033 | **6.8%（約 66 秒）** |
| P4（前任リスト） | 554 / 546 / 550 / 548 | 1.5%（約 8 秒） |
| 後退解析 合計 | 2,087 / 2,144 / 2,156 / 2,172.8 | 4.1%（約 86 秒） |

で、P2 の 66 秒に対して測れた差は 2 秒。⚠️ **この幅自体も4本以下の観測**であって、
ばらつきの上限ではない。

### 記録 #8 への含み

言えるのは **「#8 の P2 −812 秒のうち、バッファ確保が占める割合は大きくない」** まで。
残りは辞書引きそのものを消したぶんと見てよいが、⚠️ **辺ごとの PyLong 生成
（`nba[:nbn]` が作る 9.4 億個）は辞書引きと不可分**で、辞書を残したまま外せない。
そこは分離できていない。

### 副産物：段ごとの振れは合計より大きい

上の表のとおり、**`buildIndex` を1バイトも触っていない P1 が 161〜180 秒（11.8%）
振れた。** 合計の 4.1% より段ごとのほうが大きい。
⚠️ **フェーズ単独の差を読むときは、合計の帯（±3%）を流用してはいけない。**
