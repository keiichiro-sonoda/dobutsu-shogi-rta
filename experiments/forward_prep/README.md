# forward_prep: 作り替えに要る全探索側の準備を、本物の全探索に組み込んで測る（記録試行ではない）

番号を取らず、`impl/` を作らず、タイムを `results/` にも README の記録表にも載せない。

**新しい工夫を試す実験ではなく、見積もりの中の外挿を、丸ごと測った値に置き換える実験。** 全探索に足すのは、作り替えた後退解析が必要とする準備だけ。
キャッチの先行判定など、同じ部品で入れられるほかの工夫は入れない。

## 目的

[`unmove_flip`](../unmove_flip/) までで、作り替えた後退解析の見積もりは 77.39 秒、いまの作りの対応する段（P1 ＋ P2 ＋ P4 ＋ 174段ループ ＋ `R_draw` ＋ `R_uk`、
#33 本走）は 76.99 秒で、差は ＋0.40 秒だった。その内訳には測り方が2種類まざっている。

| 塊 | 秒 | 測り方 |
|---|---|---|
| 試作の後退解析のループ（絞った版） | 60.98 | 丸ごと |
| 書き出し | 2.36 | 丸ごと |
| 全局面の種類と残りの数を、ランクを添字にした配列に書く | 8.96 | **外挿**（`unmove_bench` の `degw`: 抜き出した局面で「ランクを出して1バイト書く」を1つずつ呼んだ値 × 全局面） |
| キャッチ抜きの数を数える（B1′） | 5.08 | **外挿**（`attack_count`: 抜き出した局面で生成器を1つずつ呼んだ増分 × 局面数） |

外挿の 14.04 秒は、本物の全探索の中では一度も動かしていない。後退解析だけなら作り替えのほうが 13.65 秒速い見積もり（76.99 − 60.98 − 2.36）なので、
**この準備が本物の全探索の中で 13.65 秒より軽ければ、作り替えは全体でも速い。**それを確かめる。

## 全探索に足したもの（[`patches/`](patches/)）

`impl/33_hot_layout` に対するパッチ。全探索の展開（F1。`expandRound` が入力の局面ごとに `nextBoardSeenNormal` を呼ぶ）に次の2つを足す。

1. **キャッチ抜きの数を数える**: `nextBoardSeenNormal` が呼ぶ生成器を、`nextBoardInvNormal` の写しに `attack_count` の B1′（相手の利きの一覧を局面ごとに1回作り、
   後続ごとに引く）を足した `nextBoardInvNormalNC` に替える。後続の列と順番、戻り値の規約、発見済みの表の扱いは変えない
2. **局面ごとの種類と残りの数を、ランクを添字にした 1 バイトの配列 `g_prep` に書く**: 展開した局面 p のランクを添字にして書く

**1 バイトの割り振り:**

| 値 | 意味 |
|---|---|
| 0 | 到達しない（書かれていない） |
| 1〜49 | 未知局面。キャッチ抜きの数 ＋ 1（**1 ならキャッチ抜きの数が 0**。手数 2 の負けになる局面） |
| 0xFE | トライ負け局面 |
| 0xFF | キャッチ局面 |

1 局面の後続は多くても 48 なので、未知局面は 1〜49 に収まる。配列は 855,232,344 バイトで、発見済みの表と同じく最初に1回 `hugeAlloc`（2 MiB の区切りで確保して
`madvise(MADV_HUGEPAGE)`）してから 0 で埋める。確保は最初の `nextBoardSeenNormal` の呼び出し（1ラウンド目の F1 の中）。全探索のあとも手放さない
（作り替えた後退解析が読む前提。この実験は全探索だけを走らせるので、そのままプロセスが終わる）。

新しい熱い関数 `nextBoardInvNormalNC` は、`hot_layout.ld` の区画に1行足して `nextBoardSeenNormal` の前に置いた（CLAUDE.md の取り決め）。
そのぶん、後ろの熱い関数の番地はずれる。

### 番号（ランク）の出し方を2通り

いまの全探索では、展開する局面 p のランクは手元に無い（p が後続として見つかったときに `nextBoardSeenNormal` が計算しているが、待ち行列には盤面の値だけを積む）。

- **腕 `recalc`**（[`patches/recalc.patch`](patches/recalc.patch)。C だけ）: `nextBoardSeenNormal` の頭で p のランクを計算し直し、書く行を先読みしてから生成器を回し、
  最後に1バイト書く
- **腕 `carry`**（[`patches/carry.patch`](patches/carry.patch)。C と Python）: 後続として見つけたときのランク（`nextBoardSeenNormal` がもう計算している `r[i]`）を、
  初見の後続と同じ並びの 4 バイトの列に積み、Python 側の待ち行列にも盤面の塊と同じ区切りで `array("I")` の塊として持つ（`queue_rank`）。
  `queuePush` は盤面の塊とランクの塊に同じ切り方を当てるだけで、盤面の待ち行列の区切り方（500万件ずつ）と並びは変えない。初期局面のランクは `forwardInit` で
  `rankBoard` から出す。展開するときは、取り出した塊と同じ位置のランクを `expandRound` に渡して読む

`carry` の変更は、待ち行列の盤面の側を1行も変えずに並べて持つ形にできたので、作った。

## 一致の検査（[`run_verify.sh`](run_verify.sh)。計時には使わない3本）

`old`（`impl/33` そのまま）・`recalc`・`carry_check`（`carry` に `-DPREP_CHECK` を足したビルド。積んだランクを盤面から計算し直して比べ、食い違いを数える）を
1本ずつ全探索だけ走らせる。

- **全探索の出力が #33 と同じ**: 全探索の側の `dat/`（`win001te_*` と `lose000te_*`）が #33 本走の `dat/` の同じ名前のファイルとバイト一致、`forward.tsv` の件数の列
  （`round`〜`n_try_total`）が `results/33_hot_layout/forward.tsv` と一致、全探索が後退解析に渡す3本の列（未知局面・キャッチ局面・トライ負け局面）の sha256 が
  並びまで含めて `old` と一致（未知局面の列の並びは展開の順そのもので、後退解析の採番順を決める）
- **書いた配列が正しい**（[`check_prep.c`](check_prep.c)）: 全ランクで、`cls`（`unmove_catch`〜`unmove_flip` と同じ「ランクを添字にした種類」。`runs/unmove_flip/cls.bin` を、
  sha256 が同じことを確かめて使う）が 0 なら配列も 0。#33 本走の `dat/` の全局面で、キャッチ局面なら 0xFF、トライ負けなら 0xFE、未知局面ならキャッチ抜きの数 ＋ 1。
  キャッチ抜きの数の正解は、いまの生成器（`impl/33` の `nextBoardInvNormal`）で後続を作り、後続のランクで `cls` を引いて 2 でないものを数えたもの（B2 と同じ数え方）
- **`carry` の積んだランク**: 検査用ビルドで、全局面で計算し直したランクとの食い違いが 0。配列が `recalc` の配列とバイト一致

正解の取り方について（`unmove_prune` で `cls` を正解に使って外した件を踏まえて）: ここで `cls` を正解に使うのは「到達局面の種類」と「後続がキャッチ局面か」で、
どちらも到達局面についての問い（展開される局面と、その後続は、どれも到達局面）なので `cls` で足りる。到達しない番号は「書かれていない」ことだけを見る。

計時の門番の各本でも、全探索の出力の照合（`dat/`・`forward.tsv` の件数の列・3本の列の sha256）を毎回行う（[`run_one.sh`](run_one.sh)）。

## 計時の門番（[`run_all.sh`](run_all.sh)）

**全探索だけを完走させる形**（`gate_17_forward` と同じく、後退解析は走らせない。[`driver.py`](driver.py) が `searchAll()` だけを呼ぶ）。

- 腕は `old`・`recalc`・`carry`。各腕6本、計18本。3本ずつの組を6つ並べ、組の中の並びに3腕の6通りの並べ方を1回ずつ当てる。どの腕も組の中の1・2・3番目に2回ずつ来る:
  `t1` old recalc carry / `t2` recalc carry old / `t3` carry old recalc / `t4` old carry recalc / `t5` carry recalc old / `t6` recalc old carry
- どの本も `numactl --cpunodebind=0 --membind=0` で固定。各本の前にノード0の 2 MiB 以上の空きブロックを読んで `logs/<ラベル>_hugefree.txt` に残し、
  **8 GiB に満たなければ走らせずに止めて本人に知らせる**（全探索だけなら、巨大ページを頼むのは発見済みの表 0.11 GB と配列 0.86 GB）
- 出すもの: `forward_summary.tsv` の段ごとの秒（とくに F1）、F1 のユーザー時間とカーネル時間、F1 の minor fault、ピーク RSS（`/usr/bin/time -v`）、
  `thp_fault_fallback` の前後差（0 でなければ止める）、周波数の標本
- 検定の表は `experiments/gate_stats.py forward_prep forward`（`logs/gate_stats.txt`）。腕ごとの平均と差は [`summary.py`](summary.py)（`logs/summary.txt`）

**判定の量は F1 の秒の差（各腕の平均 − `old` の平均）。** 全探索の合計（`forward_total`）の差も並べる（`carry` は待ち行列に積む Python 側の仕事が F5 に乗るので、
合計でも見る）。**2つの腕をそれぞれ `old` と比べるので、`gate_stats.py` の p 値と区間は多重比較未補正。**

### 換算

作り替えた後退解析の見積もり ＝ 試作のループ 60.98 ＋ 書き出し 2.36（どちらも `unmove_flip` の `pruned` の中央値）＋ **全探索の F1 の差（丸ごと測った値）**。
これを、いまの作りの対応する段（76.99 秒）と比べる。外挿の 14.04 秒に対して、丸ごと測った値が何倍だったかも書く。

## 止める条件（回す前に決めた）

1. **一致の検査が1つでも外れたら計時をしない**（`run_all.sh` が `logs/verify.txt` の PASS を見る）。食い違いは種類ごと（到達しない番号・キャッチ局面・トライ負け局面・
   未知局面、全探索の出力のどれか）に分けて報告する
2. **計時の門番の本で、全探索の出力の照合が1つでも外れたら、そこで止める**（`run_one.sh`。`dat/` を残す）
3. **`thp_fault_fallback` の前後差が 0 でなければ止める**
4. **各本の前にノード0の巨大ページに使える空きが 8 GiB に満たなければ、走らせずに止めて本人に知らせる**

## 見込み（回す前に書いた）

全データで何も回す前に書いた。回す前にやったのは、2つの腕と `old` を、全探索の最初の16ラウンド（展開した局面 24,542,137 個。全体の約 10%）だけ
作業用の場所で回した動作確認だけ（計時はしていない。ログは残していない）。3本の列と待ち行列の残りの sha256 が `old` と同じで、展開した局面の配列の値が
いまの生成器で数え直した値と全部一致し、`carry` の積んだランクの食い違いが 0 だった。

| | 見込み | 根拠 |
|---|---|---|
| 一致の検査 | すべて通る | 足したのは数えることと書くことだけ。動作確認の範囲では通った |
| `recalc` の F1 の差 | ＋7〜＋14 秒 | B1′ は計算だけで、メモリの待ちに隠れる余地が少ないので外挿（5.08 秒）とほぼ同じに乗る。ランクの計算と1バイトの書き込みは、展開する局面ごとに 15〜30 ns（`degw` の 36 ns には抜き出しの列を読む分と、先読みの距離が短い分が入っている。ここでは書く行を生成器を回す前に先読みするので、書き込みの待ちは隠れやすい）× 246,803,167 ≈ 3.7〜7.4 秒。配列を 0 で埋める分（0.86 GB）とページを付ける分が 0.2〜1 秒 |
| `carry` の F1 の差 | `recalc` より 1〜4 秒小さい | 展開する局面ごとのランクの計算（15〜20 ns × 246,803,167 ≈ 3.7〜4.9 秒）が無くなり、初見の後続のランクを 4 バイトずつ書く分と、ラウンドごとに C の列から Python の `array("I")` へ写す分（合わせて約 1 GB）が足される |
