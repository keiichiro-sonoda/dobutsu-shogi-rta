⚠️ **これは記録試行ではない。** タイムを `results/` や README の記録表に載せない。
入力を固定して後退解析だけを走らせた比較であり、レギュレーションの

## 🔑 この企画で初めて、効果量を「複数本」で確定させた

⚠️ **記録 #7 以降ずっと「1本の壁時計では効果量を確定できない」と書いてきた。**
#10・#11 は全探索そのものを変えたのでフィクスチャが使えず、門番も1本しか取れなかった。

**記録 #12 は全探索の出力を変えない**ので、全探索が終わった直後の `dat/` を入力に、
**後退解析だけを何本でも回せる。** 方針（2026-09-17）の
「効果量はフェーズ単独を複数回で確定させる」が、やっとそのまま使える。

- 入力は `runs/g1_11_fixture/dat`（⚠️ **記録 #11 の完走から組み直したもの**。
  旧版と新版で**同じ入力**を使っている）
- ⚠️ **本走と採番順が一致しているとは言えない（当初「そろえてある」と書いたのは誤り）。**
  `tools/rebuild_forward_fixture.py` は手数別のファイルから未知集合を詰め直すので、
  **集合は復元できても並びは復元しない。** 小さく実際に回して確かめると、
  **集合は一致したまま 2,925 件中 2,903 件（99.2%）の位置が変わった。**
  P4 は採番順に反応する段なので、**下の効果量はこの入力でのもの**で、
  本走の採番順にそのまま当てはまるとは言えない（→「本走の P4 とは一致していない」）
- **旧版（`impl/11_c_seen`）と新版（`impl/12_c_predecessors`）を交互に3本ずつ**
  （`old1 new1 old2 new2 old3 new3`）。⚠️ 交互にするのは機械のドリフトが片方に偏らないため
- 各本で**オラクル174行を通した**（6本とも PASS）

```bash
experiments/gate_12_c_predecessors/run_all.sh > exp_gate12.out 2>&1
```

#### ⚠️ 本走の P4 とは一致していない

| | 本走 | 門番3本 | 門番のほうが |
|---|---|---|---|
| 旧（`impl/11`） | 548 | 567 / 574 / 570（平均 570.33） | **+4.1%** |

⚠️ **門番のほうが旧新どちらも遅い。** 新版3本の sd は 0.58 秒しかないので、
156 と 165.67 の差を同一条件のばらつきでは説明しにくい。
⚠️ **原因は分離していない。** 上の採番順の違いとも、本走は全探索と同じプロセスで
続けて走る（アロケータとページキャッシュの状態が違う）こととも読める。
🔑 **旧新の比較そのものはこれに影響されない**（同じ入力・同じ手順で交互に取っている）。
⚠️ ただし効果量 −404.67 秒はこの入力での値で、
**本走の差（548 → 156 ＝ −392）とは 3% ずれている。**
