# 門番: 174段ループをC側へ移すと、その段がどれだけ落ちるか

⚠️ **これは記録試行ではない。** タイムを `results/` や README の記録表に載せない。
入力を固定して後退解析だけを走らせた比較であり、レギュレーションの
「空の `dat/` から完走」を満たしていない。

## 全探索を触らないので、複数本取れる

記録 #14 は全探索を1バイトも変えない。全探索が終わった直後の `dat/` を入力にすれば、
**後退解析だけを何本でも回せる**（記録 #13 は全探索そのものを変えたのでこれができず、
門番を1本しか取れなかった）。

- **旧版（`impl/13_c_expand`）と新版（`impl/14_c_retreat`）を交互に3本ずつ**
  （`old1 new1 old2 new2 old3 new3`）。交互にするのは機械のドリフトが片方に偏らないため
- 各本で**オラクル174行を通した**（6本とも PASS）。**止める条件はこれだけで、
  速度では止めない**

```bash
experiments/gate_14_c_retreat/run_all.sh > exp_gate14.out 2>&1
```

⚠️ **入力は本走と同じ採番順ではない。** フィクスチャは完走した `dat/` から
`tools/rebuild_forward_fixture.py` で組み直したもので、**集合は復元できるが並びは
復元しない**（`tests/test_rebuild_forward_fixture.py` が固定している）。
174段ループは採番順に反応する段なので、**下の効果量はこの入力での値**であり、
本走の値として読んではいけない。旧新を同じ入力で交互に比べるぶんには影響しない。

### 触っていない段（対照群）

| 段 | 旧 3本 | 新 3本 | 平均差 |
|---|---|---|---|
| P0 読み込み | 92 / 92 / 93 | 94 / 96 / 94 | **+2.3** |
| P1 索引 | 20 / 20 / 20 | 21 / 20 / 20 | +0.3 |
| P2 後続生成 | 194 / 193 / 220 | 222 / 190 / 197 | +0.7 |
| P4 前任リスト | 162 / 164 / 170 | 169 / 164 / 165 | +0.7 |

⚠️ **P0 は3本とも新版のほうが高い（+2.3 秒 / +2.5%）。原因は分かっていない。**
`loadForwardResult` は1行も変えていないので効果ではありえず、
**交互の取り方が `old → new` の順に固定されている**ぶん、対のなかで後に走るほうへ
系統的に乗る何か（ページキャッシュなど）を拾っている可能性がある。
記録 #12 の門番も同じ並びだったので、**この取り方では分離できない**。

P2 は旧の old3 が 220、新の new1 が 222 と両側で跳ねていて、平均差は +0.7 秒。
1本だけ見て読まないこと。

### メモリ

**ピーク RSS は 13.839 → 13.827 GiB**（−0.012）。3本ずつ完全に同じ値が出た。

⚠️ **下がった理由は確かめていない。** 深さごとの Python の list と `PyLong` が、
あらかじめ確保した `array("I")`（`n_uk` 要素 ＝ 398 MB）より大きい瞬間があった、
と読めるが、分離して測ってはいない（**推定**）。
