# 門番: P2 後続生成をC側へ移すと、その段がどれだけ落ちるか

⚠️ **これは記録試行ではない。** タイムを `results/` や README の記録表に載せない。
入力を固定して後退解析だけを走らせた比較であり、レギュレーションの
「空の `dat/` から完走」を満たしていない。

## 旧新8本ずつ、並びは `old new new old`

この門番は後退解析しか呼ばないので、全探索フィクスチャがそのまま入力に使える。
記録 #15 は `expandRound`（全探索側）にも手を入れているが、変わるのは空入力の
ラウンドの挙動だけで、ここでは全探索を1周も回さない。

```bash
experiments/gate_15_c_successors/run_all.sh > exp_gate15.out 2>&1
```

- **旧版（`impl/14_c_retreat`）と新版（`impl/15_c_successors`）を8本ずつ**
- 各本で**オラクル174行を通した**（16本とも PASS）。**止める条件はこれだけで、
  速度では止めない**。辺の総数も16本とも 938,671,869（未発見の後続 0）で一致

⚠️ **入力は本走と同じ採番順ではない。** フィクスチャは完走した `dat/` から
`tools/rebuild_forward_fixture.py` で組み直したもので、**集合は復元できるが並びは
復元しない**（`tests/test_rebuild_forward_fixture.py` が固定している）。
P2 は採番順に反応する段なので、**下の効果量はこの入力での値**であり、本走の値として
読んではいけない。旧新を同じ入力で交互に比べるぶんには影響しない。

## なぜ3本ずつではなく8本ずつか

[`gate_14`](../gate_14_c_retreat/) は **P2 を1行も変えていない旧新6本**を取っている。
つまり P2 の素の揺れの標本が先にあった:

```
190  193  194  197  220  222   （秒・同一コード・同一入力）
平均 202.7 / sd 14.4 / 変動係数 7.1%
```

174段ループの揺れ（sd 2.52 / 0.86%）より一桁悪い。見込んでいた効果量は 30〜70 秒で、
3本ずつだと低い側に出たときに区間が 0 を跨ぐ。8本ずつなら跨がない。

## `old new` の固定順で出ていた P0 の差は消えた

[`gate_14`](../gate_14_c_retreat/) は `old new` の固定順で、**P0 が3本とも新版のほうが
高かった**（92/92/93 → 94/96/94、+2.3 秒 / +2.5%）。`loadForwardResult` は1行も
変えていないので効果ではありえず、「対のなかで後に走るほうへ系統的に乗る何か」と
分離できていなかった。

今回 `old new new old` にしたところ、**P0 の差は −0.25 秒（95% 区間 −2.06 〜 +1.56）**に
なった。位置の効きが4本ごとに相殺される並びなので、**`gate_12` と `gate_14` の P0 の差は
並びの人工物だったと読める**。

⚠️ **ただしこれは「並びを変えたら消えた」という1回の観測で、機序は特定していない。**
ページキャッシュの温まり方を疑ってはいるが、測っていない。

## メモリ — 新版のほうが 16.6 MiB 高い

**ピーク RSS 14,498,441 → 14,515,422 KiB（13.8268 → 13.8430 GiB、+16,981 KiB ＝ +16.6 MiB）。**
**8本と8本が完全に分離している**（旧の最大 14,499,136 < 新の最小 14,514,988）ので、
揺れではない。

⚠️ **原因は分離できていない。** 新版が P2 で余分に持つのは中継バッファ **256 KiB** だけで、
16.6 MiB の 1.5% にしかならない。`succ_off` と `cnt` は先に確保する形に変えたが、
最終的に触るページ数は伸ばした場合と同じはず。`succ` の伸ばし方（1回あたり 9.4 要素 →
65,536 要素）が効いている可能性が残っている。
