# 門番 #17 (後退解析側): 書き出しの `set(...)` だけを1変数にする

⚠️ **これは記録試行ではない。** 番号を取らず、タイムを `results/` にも README の記録表にも
載せない。入力を固定して後退解析だけを走らせた比較で、レギュレーションの
「空の `dat/` から完走」を満たしていない。

全探索側は [`gate_17_forward`](../gate_17_forward/) が別に測っている。

## なぜ要ったか

`#17` は書き出しの `set(...)` を外したので、ファイルに並ぶ順序が「集合の反復順」から
「渡された並びそのまま」に変わる。本走ではそれが採番順を動かし、P2・P4・174段ループの
局所性まで変える。だから**本走の1本では「書き出しが速くなったぶん」と「採番順が
動いたぶん」が混ざる**。`#16` の門番と同じ形の問題で、CLAUDE.md にも規約として置いてある。

ここでは**両腕に同じフィクスチャを渡す**。`#16` と違って形式は変えていないので、
腕ごとに入力を作り直す小道具（`#16` の `convert_fixture.py`）が要らない。

| | |
|---|---|
| 腕 | `old` = `impl/16_raw_binary`（`set(...)` あり）／ `new` = `impl/17_no_set`（外した） |
| 入力 | 両腕とも `runs/g1_11_fixture_bin/dat`（51ファイル・1.9 GB の生バイナリ、**同一のバイト列**） |
| 並び | `old new new old` を2回、計 **8本**（対で向きを入れ替える） |
| 所要 | 52分。8本ともオラクル174行に一致 |

`runs/` は git 管理外なので、フィクスチャが無い環境では
`tools/rebuild_forward_fixture.py <元の dat/> <その run の main.log> <出力先 dat/>`
で組み直す（出力は必ず `.bin`）。⚠️ **組み直すと採番順は元と変わる。**
両腕に同じものを渡すぶんには影響しない。

### 両腕とも片ノードに固定した

`numactl --cpunodebind=0 --membind=0` を両腕に付けた。[`numa_bind`](../numa_bind/) で、
固定すると P2 の標準偏差が 15.69 → 0.71 秒に縮むことが分かっている。腕の扱いは
対称なので偏りは入らないが、⚠️ **この帯は「固定した条件での帯」で、固定していない
本走には移せない。**

## 入力が同一なら、動くのは書き出しの段だけ

表は [`../gate_stats.py`](../gate_stats.py) が [`logs/`](logs/) の生ログから組み立てる
（`python3 experiments/gate_stats.py gate_17_no_set retreat`）。

| 段 | `old` 4本 | `new` 4本 | 差 | t | 自由度 | p | 95% 区間 |
|---|---|---|---|---|---|---|---|
| P0 読み込み | 4.00（sd 0.00） | 4.00（sd 0.00） | +0.00 | 0.00 | 6.00 | 1.0000 | +0.00 … +0.00 |
| P1 索引 | 20.50（sd 0.58） | 20.00（sd 0.00） | -0.50 | -1.73 | 3.00 | 0.1817 | -1.42 … +0.42 |
| P2 後続生成 | 106.00（sd 1.41） | 105.25（sd 0.50） | -0.75 | -1.00 | 3.74 | 0.3776 | -2.89 … +1.39 |
| P4 前任リスト | 166.00（sd 1.15） | 165.00（sd 0.82） | -1.00 | -1.41 | 5.40 | 0.2123 | -2.78 … +0.78 |
| **174段＋残差** | 109.38（sd 0.59） | 74.23（sd 0.49） | -35.15 | -92.05 | 5.79 | < 0.0001 | -36.10 … -34.21 |
| 後退解析 合計 | 405.88（sd 3.50） | 368.48（sd 1.18） | -37.40 | -20.26 | 3.68 | < 0.0001 | -42.71 … -32.10 |

**下がったのは174段＋残差だけ。−35.15 秒（区間 −36.10 … −34.21）。**
P0・P1・P2・P4 はどれも区間が 0 をまたぐ。合計の −37.40 と −35.15 の差 2.25 秒は、
P1・P2・P4 の点推定（−0.50 / −0.75 / −1.00）の和とちょうど一致する。

⚠️ **P0〜P4 は `main.log` の表示値で、`s2hms()` が秒未満を切り捨てている。**
だから4段の標本は整数秒で、切り捨てたぶん（1段あたり最大1秒）は
「174段＋残差」に寄る。両腕に同じだけ寄るので差には出ないが、
**この表の 109.38 / 74.23 を「174段ループそのものの秒」として読まない。**
`174段＋残差 = 後退解析合計 − 測った4段`（`tools/noise_table.py` と同じ定義）。

## レバーが実際に並びを動かしたことの確認

1組目（`g1a` / `g1b`）は `dat/` を残して突き合わせた。出力は
[`logs/order_check.txt`](logs/order_check.txt)。

「手つかず」は**ファイル名では判定できない**。`unknown*` は `loadAllUnknownBoards()`
が全部読んで消し、`writeUnknownChunks()` が番号を 0 から振り直して書くので、
同じ名前でも中身は別物になる。`old` の出力が元のフィクスチャと**バイト同一**か
どうかで分ける。

| | |
|---|---|
| 手つかず（`old` が元フィクスチャとバイト同一） | 31 ファイル（`win001te_*` 29・`lose000te_*` 2。`appendFamily()` は読むだけ）。両腕でも同一 |
| 後退解析が書いた | 182 ファイル。**うち 180 が両腕でバイト違い** |
| 例外 | `lose172te_000.bin`（3局面。3! = 6 通りのうちの1つが偶然そろった）と `lose174te_000.bin`（0局面） |

集合が同じことは別に見ている。`tools/fingerprint_dat.py <g1a の dat> <g1b の dat>` が
**176項目一致・照合した局面数 246,803,167**。つまり**中身は同じで並びだけが動いた**。
