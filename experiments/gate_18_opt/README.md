# 門番 #18: `gcc` の最適化段だけを1変数にする

⚠️ **これは記録試行ではない。** 番号を取らず、タイムを `results/` にも README の記録表にも
載せない。全探索側は後退解析を走らせておらず、後退解析側は入力を固定しているので、
どちらもレギュレーションの「空の `dat/` から完走」を満たしていない。

## 仕掛け — 全腕とも同じソース

記録 #18 は `Makefile` の `gcc` 行に `-O<段>` を足すだけで、C も `.h` も Python も
`#17` とバイト同一。門番は `Makefile` を通さず `gcc` を直に叩くので、
**全腕とも `impl/17_no_set/` のソースを使い、動くのは `CFLAGS` だけ**にできる。

| 腕 | `gcc` に足すもの |
|---|---|
| `o0` | **なし**（`-O0` と明示しない。`#17` までの `Makefile` と字面を揃える） |
| `o1` | `-O1` |
| `o2` | `-O2` |
| `o3` | `-O3` |
| `o2n` | `-O2 -fno-semantic-interposition` |

⚠️ **`-Ofast` は入れていない。** 危険だからではなく**得るものがゼロだから**。
`.c`/`.h` に浮動小数点が1つも無い（`float`/`double`/`<math.h>` すべて 0 件）ので
`-ffast-math` は何もしない。`-march=native` は別のレバーなので混ぜていない。

両腕ならぬ5腕とも `numactl --cpunodebind=0 --membind=0` で片ノードに固定した。
この帯は固定した条件での帯で、固定していない本走には移せない。

## 判定は「全探索合計」で、規則は測る前に決めた

完走タイムの雑音はほぼ全部が後退解析から来ている。4本ずつでの95%半幅は
**全探索合計 1.4〜5.7 秒**に対し**完走タイム 28 秒**（`numa_bind` の固定なし8本で
後退解析合計 sd 16.25）。かつ**いちばん計算寄りの段 F1 が全探索側に居る**。

> **`-O3` と `-O2` の差の95%区間が 0 を含むなら `-O2` を採る。**
> 理由は速さではなく、コードサイズを増やさない慣例線だから。
> ⚠️ **「わずかに速かったほう」で選ばない。**

### 答え: `-O2`

`o3 − o2` の95%区間が **−7.79 … +8.26** で 0 を含む。判定規則どおり **`-O2` を採る**。

**下がったのは F1 展開だけ。** F0 / F2 / F5 / F6 はどの腕どうしでも区間が 0 をまたぐ。
全探索合計の −56.50 秒（`o2` 対 `o0`）は、F1 の −55.83 でほぼ全部説明できる。

⚠️ **`-O` が効くのは計算の段だけ**という予測どおりになった。C の監査では、
時間を食う `predScatter` / `predCount` / `retreatStep` / `seenInsert` はどれも
DRAM レイテンシ律速で、`-O` が確実に効くのは `nextBoardInvNormal` / `invBoard` /
`normalBoard` の純ビット演算（約3.5億回、配下の `normalBoard` 呼び出しは
約12〜13億回）だけ。その3つはどれも F1 の中に居る。

### 段より雑音が大きい段がある

⚠️ F2 と F5 は腕にかかわらず時々跳ねる（`o0` の1本で F2 16.25 / F5 15.85、
`o3` の1本で F2 16.07 / F5 18.24）。これが全探索合計の sd を 3.4〜5.3 秒に
押し上げていて、`o3 − o2` の区間が ±8 秒になった主因。**F1 単独なら sd 0.5〜1.3 秒**で、
そちらでは `o3 − o2` が −1.49（区間 −3.05 … +0.08）とぎりぎり 0 をまたぐ。
どちらの見方でも `-O2` が選ばれる。

### `-fno-semantic-interposition` は F1 では効いている

`o2n − o2` は**全探索合計では −1.98（区間 −7.84 … +3.88）で 0 をまたぐ**が、
**F1 では −3.75（区間 −4.91 … −2.58）で 0 をまたがない**。

`-fPIC -shared` では同じ `.so` の中の呼び出しもインライン展開されない
（実行時に差し替えられうるため）。`objdump -d` で数えると、`normalBoard` への
`call` は `-O2` で **3 箇所**、`-O2 -fno-semantic-interposition` で **0 箇所**になる。
`nextBoardInvNormal` → `normalBoard` は**深さ2 で約12〜13億回**通る。

⚠️ **この記録には入れない。** `-O` の段とは別の軸なので、出た値をそのまま
`#19` の事前登録にする。門番を2回走らせずに済む。

### 自己検査 — `o0` が `gate_17_no_set` の帯に入った

`o0` のビルドは [`gate_17_no_set`](../gate_17_no_set/) の `new` 腕と同一で、
フィクスチャも同じ。外れていたらこの門番のどこかがおかしい、という自己検査になる。

| | `gate_17_no_set` の `new` 8本 | ここの `o0` 4本 |
|---|---|---|
| P0 / P1 / P2 / P4 | 4.00 / 20.25 / 105.62 / 165.50 | 4.00 / 20.25 / 105.75 / 165.25 |
| 後退解析 合計 | 368.48（sd 1.18） | 369.34（sd 2.26） |

### P2 だけ、全探索より下がり幅の割合が大きい

⚠️ 事前には「後退解析は DRAM 律速なので、下がり幅の割合は全探索より小さいはず」と
登録していた。**まとめて見れば当たっている**（4段の合計 365.34 → 298.50 = −18.3% 対
全探索合計 −30.5%）が、**P2 単独は 105.75 → 68.50 で −35.2%** と全探索を上回った。

理由は呼び出し表にある。`-O` が効く純ビット演算の `nextBoardInvNormal` は
**F1 だけでなく P2 の中にも居る**。`buildSuccRange` → `nextBoardIndexNormal`
（約 9,949 万回）→ `nextBoardInvNormal` という経路で、F1 側の
`expandRound` → `nextBoardSeenNormal`（約 2.47 億回）→ `nextBoardInvNormal` と
同じ関数を通る。C の監査は経路を挙げていたが、**P2 に計算がどれだけ乗っているかを
見落としていた**。

## 答えが変わっていないことの確かめ方

⚠️ **手数別174行はオラクルだが、あれは後退解析の出力なので全探索だけでは出ない。**
CLAUDE.md の「オラクル検証は実験でも毎回通す」に対しては3つで閉じた。

1. **全探索の毎本**: `総未知 + 総勝ち + 総負け` が `oracle/totals.tsv` の
   `reachable_total` と一致。**20本とも 246,803,167**
2. **後退解析の毎本**: `tools/verify_log.py` の174行
3. **成果物のバイト比較**: 全探索側は `keep` した5本を突き合わせて
   **51ファイル / 1,974,425,336 バイトが全腕でバイト同一**。後退解析側も
   `o0` と `o2` の **213ファイル / 1,974,425,336 バイトがバイト同一**
   （[`logs/bytecompare_arms.txt`](logs/bytecompare_arms.txt)）。
   `-O` は値も順序も1ビットも変えない。**これがこの門番でいちばん強い検査**で、
   毎本の全局面数は件数しか見ていない

## 警告

18記録ぶん `-O0` で走ってきたので、最適化を有効にしないと出ない警告
（`-Wmaybe-uninitialized` など）が初めて露出する可能性があった。
**5腕とも `-Wall -Wextra` で警告ゼロ**（[`logs/warnings.txt`](logs/warnings.txt)）。

事前に1箇所を疑っていた。`animal_shogi.c:95` の `int *moves;` は `default:` 経路
（`koma ∈ {1,2,3,5}`、実際に到達する）で未設定のまま抜ける。直後の
`if (!moves_num) continue;` で読まれないので挙動は正しいが、値域解析が
`moves` と `moves_num` の相関を追えないと警告が出る。GCC 13.3.0 は追えていた。

⚠️ `-Wextra` は記録実装の `Makefile` に入れていない。入れると次の記録との差分が2つになる。

## この門番が言っていないこと

- **完走タイム。** 全探索側は後退解析を走らせておらず、後退解析側は入力を固定している
- **本走の後退解析がどう動くか。** ここのフィクスチャは `tools/rebuild_forward_fixture.py` で
  組み直したもので採番順が本走と違う。記録 #17 で、採番順が P4 を 158 → 70 秒
  動かしたことが分かっている
- **`-march=native` の効果量。** 別のレバー
- **F1 の −55.83 秒の内訳。** 「計算の段だから」までで、どの最適化がいくら効いたかは
  分けていない
- 固定していない条件での帯（上記のとおり）
