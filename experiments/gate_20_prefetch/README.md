# 門番 #20: 先読み4か所と `moves = NULL;`

⚠️ **これは記録試行ではない。** 番号を取らず、タイムを `results/` にも README の記録表にも
載せない。入力を固定して片方の段だけを走らせる門番で、レギュレーションの
「空の `dat/` から完走」を満たしていない。

## なぜ測り直したか

[`lever_scan`](../lever_scan/)（記録ではない）で、先読みは後退解析 −48.07 秒・全探索 −13.47 秒と
いちばん大きく効いた。ただしあちらは7腕を `base` に対して引いていて多重比較は未補正で、
**選んだ腕の効果は上に偏っている**。記録 #20 の証拠には使わず、同じ問いを2腕で測り直した。
比較は1対1なので、多重比較の補正は要らない。

| | |
|---|---|
| 腕 | `old` = `impl/19_c_gather` ／ `new` = `impl/20_prefetch`。両腕とも実装の `Makefile`（`-O2`）でビルド（[`build_arm.sh`](build_arm.sh)） |
| 全探索 | 空の `dat/` から `searchAll()` だけ。`old new new old` × 2 = 8本、17分 |
| 後退解析 | `runs/g19_fixture_bin/dat` から `retreatAnalysis()` だけ。同じ並びで8本、21分 |
| 固定 | 両門番とも `numactl --cpunodebind=0 --membind=0` |

後退解析の入力は、`impl/19` の全探索が書いた `dat/` そのもの（lever_scan と同じ）。
`tools/rebuild_forward_fixture.py` で組み直した入力は並びが本走と違い、先読みの効き目は並びに
依存する（lever_scan のマイクロベンチで一様 0.21 倍・局所 0.18 倍）。

## 止める条件には掛からなかった

測る前に決めた条件は1つだけ。**先読みを入れた4段（F1・P1・P2・P4_scatter）のどれかで、
`new − old` の区間が 0 をまたがずに上（遅くなった）なら、本走の前に止める。**
区間が 0 をまたぐだけなら止めない。判定は [`stop_rule.py`](stop_rule.py) が出す。

### 対照の段

触らないはずの段（F0・F2・F5・F6・P0・P2_free・P4_count・R_dtm・174段・R_draw・R_uk）は、
**R_uk を除いて区間が 0 をまたいだ。** R_uk は −0.95 ミリ秒（区間 −1.64 … −0.26 ミリ秒、p 0.016）で
0 をまたがない。R_uk は Python の `writeUnknownChunks` で、今回の変更（C の先読みと `moves`）は
通らない。対照を11段並べているので、5% 水準で1つが外れるのは偶然でも起こりうる範囲で、
**機序は分けていない**。大きさはミリ秒で、判断には効かない。

## lever_scan との比べ方

lever_scan の値は**参考**で、上に偏っている可能性があると測る前に書いてあった。
同じ段で並べると、どれも同じ桁に収まった。

| 段 | この門番（`new − old`） | lever_scan（`pf − base`） |
|---|---|---|
| F1 | −15.38 | −14.84 |
| P1 | −2.11 | −2.20 |
| P2 | −0.68（0 をまたぐ） | −1.35（0 をまたぐ） |
| P4_scatter | −44.60 | −44.39 |

⚠️ 入力も並びも同じだが、腕の数・1腕あたりの本数・並べ方が違う。**差どうしを引き算して「偏り」を
出さない。**

## この門番が言っていないこと

- **本走の値。** 入力は本走と同じ並びだが、`numactl` で固定していて本走そのものではない。
  門番と本走の値を直接引き算しない（CLAUDE.md）
- **`moves = NULL;` の効き目。** 先読みと同じ腕に入っているので分けられない。
  読まれない経路の初期化で、どの段にも効かないと予測していた
- **P2 に先読みが効くかどうか。** この本数では確定できなかった。効かないという意味ではない
