# 門番 #21: 索引と発見済み表を巨大ページにする

⚠️ **これは記録試行ではない。** 番号を取らず、タイムを `results/` にも README の記録表にも
載せない。入力を固定して片方の段だけを走らせる門番で、レギュレーションの
「空の `dat/` から完走」を満たしていない。

## 何を比べるか

[`lever_scan`](../lever_scan/)（記録ではない）で、巨大ページは後退解析 −22.75 秒・全探索 −10.29 秒
だった。ただし7腕を `base` に対して引いていて多重比較は未補正で、しかも `base` には先読みが
入っていなかった。記録 #21 の証拠には使わず、先読みの入った #20 の上で2腕で測り直す。

| 腕 | 中身 |
|---|---|
| `old` | `impl/20_prefetch` の `.c` / `.h` ＋ **`impl/21_hugepages` の `.py`** ＋ `Makefile`（＝ #21 から C の変更だけを戻したもの） |
| `new` | `impl/21_hugepages` |

⚠️ **`old` を #20 そのものにしない。** #21 は Python にユーザー時間とカーネル時間の計装を入れている。
計装が片方の腕にだけ入ると、計装の費用が巨大ページの効果に混ざる（#19 の門番が `old` を
「#18 ＋ 計装だけ」にしたのと同じ理由）。腕は [`build_arm.sh`](build_arm.sh) が組む。

| 門番 | 走らせるもの | 並び |
|---|---|---|
| 全探索 | 空の `dat/` から `searchAll()` だけ | `old new new old` × 2 = 8本 |
| 後退解析 | `runs/g19_fixture_bin/dat`（`impl/19` の全探索の出力そのもの）から `retreatAnalysis()` だけ | 同じ |

両門番とも `numactl --cpunodebind=0 --membind=0` で片ノードに固定する。比較は1対1なので、
多重比較の補正は要らない。全16本の出力を基準と照合する（全探索は入力の md5 一覧の sha256、
後退解析は #20 本走の `dat/`）。前後の `/proc/vmstat` も残す。

## 止める条件（測る前に決めた。[`stop_rule.py`](stop_rule.py) が判定する）

1. 巨大ページを入れた3段（F1・P1・P2）のどれかで、`new − old` の区間が 0 をまたがずに上（遅くなった）
2. `new` のどれか1本で、表を捨てる直前の `AnonHugePages` が表の全部（全探索 4,096 MiB、
   後退解析 8,192 MiB）に届かない。または `thp_fault_fallback` の前後差が 0 でない。
   **レバーが効いていないので、測った差は巨大ページの効果ではない**

区間が 0 をまたぐだけなら止めない。

## 予測（門番を回す前に書いた）

大きさは弱い予測としてだけ書く（lever_scan の値は上に偏っている可能性があり、しかも
先読みの入っていない `base` との差だった）。

| | 予測（`new − old`） | 根拠 |
|---|---|---|
| **P2** | 下がる。区間が 0 をまたがない。**F1・P1・P2 の中で最大** | lever_scan 単独で −16.12。全部入りと各腕の和の差が −1.31 で、先読みと待ちを取り合わなかった |
| P1 | 下がる。区間が 0 をまたがない。lever_scan 単独の −5.91 より小さい（弱い予測） | 全部入りと各腕の和の差が +1.44 |
| F1 | 下がる。区間が 0 をまたがない。lever_scan 単独の −10.28 より小さい（弱い予測） | 全部入りと各腕の和の差が +3.87 |
| 対照（F0・F2・F5・F6・P0・P4_count・P4_scatter・R_dtm・174段・R_draw・R_uk） | 誤差内 | 2つの表を使わない。P4 とループの配列は Python 側で確保している |
| P2_free・全探索の解放 | 判定しない | 解放と smaps の読みが入る区間。値と smaps の費用は報告する |
| 索引の fault（`min_P1 − min_P0`） | 2,097,153 → 4,096 前後 | 8 GiB ÷ 2 MiB。lever_scan は 4,098〜4,101 |
| minor fault の合計 | 全探索・後退解析とも約209万減 | lever_scan |
| `compact_stall` / `thp_fault_fallback` | 前後差 0 | lever_scan の全42本で 0 |
| **カーネル時間** | 全探索・後退解析とも約2秒減。**全探索は F1、後退解析は P1 に集中し、P2 はほぼ動かない** | fault が減るのは表を作る段（F1 は表を倍々に作り直し、P1 は索引を `memset` する）。lever_scan の `time.txt` で 22.33 → 20.09、13.90 → 11.98 |
| **ユーザー時間** | **P2 の短縮はほぼ全部ユーザー時間から出る。** F1 はユーザーとカーネルの両方から出る | 番地の翻訳のためのメモリ読み（ページウォーク）は CPU がやる仕事で、カーネルに入らない |
| `AnonHugePages` | `new` は表の全部、`old` は 0 | |
| ピーク RSS | 動かない | 表の大きさは同じ |
| `dat/` | 全16本が基準とバイト一致 | 並びを変えない |

⚠️ **F1 と P1 の「単独より小さい」は弱い予測。** lever_scan の「全部入り − 和」には `fnsi`・`native`・
`const` との取り合いも入っていて、先読みとの取り合いだけを表してはいない。外れたら外れたと書く。

**いちばん確かめたいのは P2 の2行（最大になる、ユーザー時間から出る）。** P2 は #20 で先読みが
効かなかった段で、「番地の翻訳待ちがボトルネック」という仮説が合っていれば、巨大ページの効果は
大きく、しかもカーネル時間ではなくユーザー時間から出る。

ユーザー時間とカーネル時間の配分は、タイマー割り込みの標本から比で割り振られる
（この計測機は `CONFIG_HZ=1000` で `nohz_full` なし）。合計は正確だが配分は標本なので、
**段ごとの合計で読む**（[`cpu_split.py`](cpu_split.py)）。
