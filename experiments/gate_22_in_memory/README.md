# 門番 #22: 中間ファイルをやめる — 待ち行列の区切り方で2腕（記録試行ではない）

`impl/22_in_memory` は、全探索が書いて同じプロセスがあとで読み戻して消していたファイルを、
メモリの受け渡しに置き換えた。

- `unexplored###.bin`（待ち行列）: F5 で書き、次のラウンドの F0 で読んでいた
- `unknown###.bin`（全探索の未知）: F2 で書き、P0 で読んでいた
- `win001te_*` / `lose000te_*`: F6 で書いたものを P0 が読み戻していた（F6 の書き出しは残す）

#21 の本走でこの4段（F0・F2・F5・P0）は計 34.7 秒で、うちユーザー時間は 5.8 秒しかない。
残りはカーネル時間 17.7 秒と、CPU の外にいる時間 11.2 秒（F2・F5 の書き込みの待ち）。
F2 と F5 は末尾のファイルを読み直して継ぎ足すので、全探索の未知 0.74 GiB と待ち行列 1.84 GiB に対して、
書いた量は **4.91 GiB**（[`io_volume.py`](io_volume.py) が #21 の `forward.tsv` の件数から数え直す）。

待ち行列は先に入れたものから取り出すので、何件ずつ取り出しても展開の順は変わらない。
区切り方だけが違う2つの形を作り、どちらを記録にするかをこの門番で決める。

## 腕

| 腕 | 中身 | 1ラウンドで展開する数 | ラウンド数 |
|---|---|---|---|
| `old` | `impl/21_hugepages` そのまま（ファイルで受け渡す） | 最大500万 | 74 |
| `chunk`（A） | `impl/22_in_memory` そのまま（回した時点では `impl/22_in_memory` ＋ `patches/chunk.patch`） | `min(5,000,000, 待ち行列の長さ)` | 74（#21 と同じ） |
| `whole`（B） | `impl/22_in_memory` ＋ [`patches/whole.patch`](patches/whole.patch)（回した時点では `impl/22_in_memory` そのまま） | そのとき並んでいる全部（幅優先の1層） | 未知（予測は下） |

門番を回した時点（83924f5）では `impl/22_in_memory` が B で、A をパッチで組んでいた。A を採ったので
`impl/22_in_memory` を A に確定させ、B をパッチにした。[`build_arm.sh`](build_arm.sh) が組む2腕のコードは同じで、
`whole.patch` を当てると回した時点の `impl/22_in_memory` とバイト一致する。

`chunk` と `whole` の差は `queuePush()` の1関数だけ（未知の持ち方、P0 の詰め方、F6 は共通。
`tests/test_impl_22_in_memory.py` が固定している）。`.c` / `.h` / `Makefile` は3腕ともバイト同一。
計装も3腕で同じ（#22 は計装を足していない）。

## 単位は完走

空の `dat/` から `python3 ./animal_shogi.py` を1本。全探索だけ・後退解析だけに分けない。
#22 から後退解析はファイルを読まないので、全探索の出力（`runs/g19_fixture_bin/dat`）から後退解析だけを
回すいままでの門番では、P0 の受け渡しを通せない。完走でも1本3分半ほど。

## 実行順（計18本、各腕6本）

[`run_all.sh`](run_all.sh)。3腕 × 6ブロックで、各腕は各位置（1・2・3番目）に2回ずつ来る。
ブロックの中で隣り合う前後の組（6通り）も2回ずつ。ブロックをまたぐ前後は揃えていない。

| ブロック | 1番目 | 2番目 | 3番目 |
|---|---|---|---|
| 1 | old | chunk | whole |
| 2 | chunk | whole | old |
| 3 | whole | old | chunk |
| 4 | old | whole | chunk |
| 5 | whole | chunk | old |
| 6 | chunk | old | whole |

どの本も `numactl --cpunodebind=0 --membind=0` で片ノードに固定する（CLAUDE.md）。

## 判定の量と、採る腕の規則（回す前に決めた）

判定の量は **J ＝ `forward_total` ＋ `P0`**（秒）。`old` と A・B でコードが違うのは、ここに入る段だけ。

- **B − A の 95% 区間が 0 を含む → B を採る**
- **B − A の区間が 0 をまたがずに下（B が速い） → B を採る**
- **B − A の区間が 0 をまたがずに上（B が遅い）ときだけ A を採る**

同点で B を採るのは、500万という数が 2021年のメモリ 2 GB に合わせたもので、外せるなら外したいから。
採った腕のコードで `impl/22_in_memory` を確定させ、採らなかった腕はパッチとしてここに残す。

比較は3本（`chunk − old`、`whole − old`、`whole − chunk`）。p 値と 95% 区間はどれも
個々の比較についての値で、**多重比較は補正していない**。

## 止める条件（[`stop_rule.py`](stop_rule.py)）

どれかに掛かったら、本走の前に止めて報告する。

1. どれかの本の `dat/` が #21 本走の `dat/` とバイト一致しない（オラクルで落ちた本も同じ扱い）。
   P0 の詰め方・初期局面・F6 の順のどれかを取り違えている
2. `chunk` の `forward.tsv` の件数の列（`n_in`・`n_win`・`n_lose`・`n_uk`・`n_new_post`）が
   `results/21_hugepages/forward.tsv` と1ラウンドでも違う（A になっていない）
3. 採った腕が `old` より遅い（J の区間が 0 をまたがずに上）

1 と 2 は [`run_one.sh`](run_one.sh) が毎本その場で見て、掛かったら `dat/` を残して止まる。

## 答えの検査

毎本、オラクル174行（`tools/verify_log.py`）と、`dat/` の md5 一覧の sha256 を
#21 本走の値 `f18f3075…`（[`results/21_hugepages/bytecompare.txt`](../../results/21_hugepages/bytecompare.txt)。
#19・#20 と同じ値）と照合する。

## 予測（門番を回す前に書いた）

大きさの根拠は #21 の本走（`numactl` なし）と #21 の門番（`numactl` あり）の値で、
この門番の `old` とは測り方が違う。大きさは弱い予測としてだけ書く。

| | 予測 | 根拠 |
|---|---|---|
| **F0 ＋ F2 ＋ F5** | B は 1 秒未満。**A は B より大きい**（A は 0.4〜1.5 秒） | ファイルの読み書きが消え、残るのは配列への積み足しだけ。ただし A は、積む局面を1回ずつ塊へ写すので、1.84 GiB ぶんの新しいページを触る（#21 の F0 は 1.84 GiB を読んで2回写し、1.08 秒） |
| **P0** | A・B とも 0.5〜1.5 秒（`old` は約 4 秒） | 詰める 1.97 GB の写しは残る |
| **全探索の CPU の外の時間**（壁時計 − ユーザー − カーネル） | A・B とも 1 秒未満（#21 本走は 11.2 秒） | 書き込みが 4.91 GiB 減る |
| **全探索のカーネル時間** | A・B とも `old` より 12 秒以上減る | F0・F2・F5 のカーネル時間（#21 の門番で `impl/21` の腕が 14.03 秒）がほぼ消える |
| F6・174段ループ・R_uk の CPU の外の時間 | 増えない（区間が 0 をまたぐか、下） | 待ちが書き込みの溜まりすぎによるものなら、減らしたぶん消える。**移ってきたら、その読みは外れ** |
| F1 | A は誤差内（区間が 0 を含む）。B は向きを登録しない | A の F1 は #21 と文がバイト同一。B は1ラウンドの作業用配列が大きくなる |
| **B − A（J）** | B が遅くはない（点推定は 0 以下で、大きさは 1 秒未満）。区間は 0 を含む見込み（弱い予測。J に入る F1 の B の向きを登録していないので） | 違いは A の塊への写しと、ラウンドごとの固定費くらい |
| P1〜R_uk（後退解析の P0 以外） | 誤差内。区間が 0 をまたがない段が出ても、差は 1% 未満 | コードも入力の並びも同じ |
| B のラウンド数 | 30〜50 | 見込みだけ。#21 の `forward.tsv` はラウンドが層に分かれていないので、層の数は数えられない |
| 全探索のピーク RSS | `old` より上がる。A で +0.5〜+1.2 GiB、B で +1.2〜+2.5 GiB | 未知 0.74 GiB と待ち行列がメモリに乗る。B は最大の層の作業用配列も増える |
| **全体のピーク RSS** | 動かない（差 0.05 GiB 未満） | ピークは P2 にある。全探索のピークは上がっても届かず、3本は P1 より前に手放す |
| `dat/` | 18本とも #21 本走とバイト一致 | 並びを変えない |
| 完走タイム | 幅を出さない | |

### B が遅かったのは、F1 と F6 のカーネル時間

`whole − chunk` の J +2.48 秒の内訳は、F0 ＋ F2 ＋ F5 が −1.61 秒（B は塊へ写さない）、
F1 が +3.43 秒（うちカーネル時間 +2.77、ユーザー時間 +0.66）、F6 が +0.67 秒（うちカーネル時間 +0.55）。
B は minor fault が A より 113.83 万回多く、マシン全体の `numa_local`（ノード内で割り当てたページ）も
約 118 万ページ多い（[`logs/judge.txt`](logs/judge.txt) の vmstat の表）。**新しいページを多く触っている。**
B の1ラウンドは最大 30,196,273 件で、展開の作業用配列（入力の写しと勝ち・負け・未知の受け皿）が
1本 240 MB になる。**機序は分けていない。** 読める候補は、大きい配列ほど毎ラウンド新しく確保されて
ページを触り直すこと（小さい配列は解放した領域が使い回される）。

### A も F1 と F6 が `old` より伸びた（カーネル時間だけ）

`chunk − old` の F1 は +0.84 秒で、**ユーザー時間の差は +0.00（区間 −0.36 … +0.37）、カーネル時間が +0.84**。
F1 の文は #21 とバイト同一なので、同じ仕事にかかるカーネルの手間が増えた。F6 も +0.56 秒（うちカーネル +0.45）。
**CPU の外の時間はほかの段へ移っていない**（F6・174段ループ・R_uk・後退解析全体とも 0.00〜0.01 秒）。
移ったのは待ちではなく、カーネル時間。**機序は分けていない。**
マシン全体の `pgmigrate_success` は `old` 13.4 万 → `chunk` 42.2 万・`whole` 43.3 万ページに増えたが、
何が移したのかは分けていない。
