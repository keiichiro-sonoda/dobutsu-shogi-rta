# 門番 #34: 後退解析を「一手前を直接作る」作りに替える（`impl/34_unmove`）

記録試行 #34 の門番。完走単位で `old`（`impl/33_hot_layout`）と `new`（`impl/34_unmove`）を比べ、本走に進むかを決める。

## 何を変えたか

[`impl/34_unmove`](../../impl/34_unmove/) は `impl/33_hot_layout` を写して、後退解析を作り替えた。実験 `unmove_bench` から `forward_prep` までで
1つずつ確かめた形を実装に移したもの。

- **全探索の側**: `forward_prep` の腕 `carry` をそのまま入れた。展開する局面ごとに、相手の利きの一覧（`attack_count` の B1′）でキャッチ抜きの数を数え
  （`nextBoardInvNormalNC`）、ランクを添字にした 1 バイトの配列に種類と数を書く。ランクは、後続として見つけたときのものを待ち行列に盤面と同じ区切りで
  積んで使う（`queue_rank`）。後続の列と順番、待ち行列の区切り方（500万件ずつ）、全探索の側の `dat/` は #33 と変えない。
  実験から足したのは1つだけ: キャッチ抜きの数が 0 の未知局面（手数 2 の負け）を、見つけた順に C の列に積む（後退解析ではランクから盤面に戻せないので、
  手数 2 の段のフロンティアに足すにはここで持つしかない。実験の試作では、後退解析の初期化で全未知局面の後続を作り直して数えていた）
- **後退解析の側**: P0（連番を振る）・P1（索引 8 GiB）・P2（後続を作る）・P4（前任の表）・174段ループを消し、次の4段に替えた
  - `U_init` 初期化: 準備の配列から手数の配列（ランクを添字にした 1 バイト）を作り、準備の配列をその場で残りの数に読み替える。キャッチ局面は手数 1、
    トライ負けは手数 0、キャッチ抜きの数が 0 の未知局面は手数 2、到達しない番号は「到達しない」の印
  - `U_loop` ループ: 手数 nd − 1 で決まった局面から、`unmove_prune` の絞った版の逆向きの生成器で前任を作り、手数を決め、手数ごとに `dat/` に書く。
    前任の候補は手数の配列だけで「未定の未知局面か」を見る（試作では種類の表 `cls` を先に引いていたが、手数の配列に「到達しない」の印を入れたので要らない）
  - `U_draw` 引き分けを拾う: 未知局面の列を順に見て、ランクで手数を引き、未定のものを集める（`unmove_flip` の書き出しと同じ形）
  - `U_uk` 引き分けを書く
- `unmove_flip` の反転を1回にする版は使わない（遅かった）。キャッチの先行判定などほかの工夫も入れない

段の対応（記録ノートにも書く）:

|---|---|
| `U_init` | P0・P1・`R_dtm`（と P2・P4 の配列の確保） |
| `U_loop` | P2・P4・174段ループ（手数ごとの書き出しを含む） |
| `U_draw` | `R_draw` |
