# 門番 #37: 逆向きの生成器で鏡像を1回にした `impl/37_mirror1` を、#36 と完走で比べる（記録試行の門番）

`old` ＝ `impl/36_bb_unmove`（記録 #36）、`new` ＝ `impl/37_mirror1`。どちらもその実装の `Makefile` でビルドする（[`build_arm.sh`](build_arm.sh)）。
作りは [`gate_36_bb_unmove`](../gate_36_bb_unmove/) を写し、答えの検査を [`gate_34_unmove`](../gate_34_unmove/) の形（後退解析の側の並びが変わる版）にした。

## 何を比べるか

`impl/37_mirror1` は `impl/36_bb_unmove` に [`experiments/mirror1_keep/patches/mirror1.patch`](../mirror1_keep/patches/mirror1.patch) を当てただけの実装。
変わるのは逆向きの生成器 `unmoveCandidates` と下請けの `unmoveRaw`・`unmovePiece`・`unmoveCaptures`・`unmoveEmit` だけで、表を作る関数・`unmoveStep`・全探索の側・
`normalBoard()`・`invBoard()`・ランク・`.py`・`Makefile`・`hot_layout.ld` は #36 とバイト同一（[`tests/test_impl_37_mirror1.py`](../../tests/test_impl_37_mirror1.py)）。

#36 までの逆向きの生成器は、手を指した直後の盤が q か鏡像の q のどちらかなので、その両方（q が左右対称なら q だけ）から手を戻し、戻した p が正規形のものだけを残していた
（戻した盤の約半分を捨てていた）。#37 は q だけから戻して正規化する。辺の本数を変えないための2つの規則:
1. q が左右対称でない: 戻した候補 c ごとに正規形 N(c) を出し、c が左右対称なら2回出す
2. q が左右対称: 今までと同じく、c が正規形のものだけを残す

**前任の候補の多重集合は #36 と同じだが、並びは変わる。** だから後退解析が局面を決める順と、後退解析の側の `dat/` の並びが変わる（#34 と同じ）。並びを保つ版は
[`mirror1_keep`](../mirror1_keep/) で作れることを確かめたが、並べ直しが得の約3分の1を食い、守れるのは答えに入らない並びだけなので入れない。答えは手数ごとに束ねた集合で見る。

## 回す前に確かめたこと

- **`impl/37_mirror1` の `.so` は、`mirror1_keep` の腕 `mirror1` の `.so` とバイト一致した**（sha256 `1730c3fdcb0b03c0…`。C もバイト一致）。だから `mirror1_keep` の
  全局面の一致の検査（到達可能な全 246,803,167 局面で、候補の数と多重集合が #36 と同じ。[`logs/verify_mirror1.txt`](../mirror1_keep/logs/verify_mirror1.txt)）がそのまま当たる
- `tests/test_impl_37_mirror1.py`: 打ち切った全探索の出力が #36 とバイト一致。そのあとの後退解析の `dat/` は、ファイルの名前と大きさ、手数ごとに束ねた集合が #36 と同じ。
  展開した局面とその前任の候補を q にした逆向きの生成器が、#36 と候補の数と多重集合で同じ（左右対称な q と、左右対称な候補が出る q を両方通し、並びが #36 と違う局面があることも見る）。
  詰め物の検査も通る。`CLAUDE.md` の「次の実装で必ず直すもの」は空だった
- **熱い関数の置き場所のずれ**（`nm`。左が #36、右が #37）: `unmoveCandidates` が 0x1183 → 0x1139 バイト（−74）に縮み、後ろの `unmoveInit`・`unmoveStep`・`unmoveDraws` は
  **−0x80（−128 バイト、64 バイトの区切り2つ）**ずれる。前に並ぶ全探索の関数（`invBoard` 0x2000・`nextBoardInvNormal` 0x20c0・`nextBoardInvNormalNC` 0x2540・
  `nextBoardSeenNormal` 0x2a00・`expandRound` 0x2f00）は動かない。`.bss` は #36 と同じ並び（大きさ 0x3f438）

  | 関数 | #36 | #37 |
  |---|---|---|
  | `unmoveCandidates` | 0x3200（0x1183 バイト） | 0x3200（0x1139 バイト） |
  | `unmoveInit`・`unmoveStep`・`unmoveDraws` | 0x43c0・0x44c0・0x49c0 | 0x4340・0x4440・0x4940 |

- `check_answer.py` を #36 本走の `dat/` 自身に当てて、`old` の形（md5 一覧）と `new` の形（176 束がすべて一致）の両方で PASS することを確かめた

## 記録にするかの取り決め（回す前に決めた）

速さだけのレバーなので、#35・#36 と同じ扱い。

- 完走の `new − old` の区間の上端が 0 より下 → **本走して記録にする**
- 区間が 0 をまたぐ → **本走せずに止めて報告する**（欠番にするかは本人が決める）
- 区間の下端が 0 より上（遅くなった）→ **本走せずに止めて報告する**

## 配置と条件

- 単位は完走（空の `dat/` から1本）。`old new new old` を3ブロック、計12本（各腕6本。[`run_all.sh`](run_all.sh)）
- どの本も `numactl --cpunodebind=0 --membind=0`。各本の前にノード0の 2 MiB 以上の空きを読んで `logs/<ラベル>_hugefree.txt` に残し、16 GiB に満たなければ走らせずに止める
- **門番の前に1本、`new` を完走させて答えの検査を通す**（[`run_trial.sh`](run_trial.sh)。計時には使わない。通らなければ `run_all.sh` は回さない）
- 回す前に、CPU 使用率（全 CPU）が 3% 以下（ほかの計算が動いていない）ことを確かめ、load average と CPU 使用率だけを残す。`impl/36_bb_unmove`・`impl/37_mirror1` に `__pycache__` が無いこと

## 止める条件（回す前に決めた）

1. 答えの検査が1本でも外れる（全探索の側のバイト一致・名前と件数・オラクル・指紋・**手数ごとの集合**のどれか。`new` の md5 一覧が本ごとに違うことも含む）
