# hugefree_need2: 巨大ページに使える空きの基準を、空き全体の減りで測り直す（記録試行ではない。2回目）

番号を取らず、`impl/` を作らず、`results/` にも README の記録表にも載せない。速さは測らない（秒は参考）。

## 目的と、1回目からの違い

走る前に確かめる「巨大ページに使える空き」の基準（`HUGEFREE_MIN_GIB` 16 GiB）は、#23 の作りにあった後退解析の索引 8 GiB を見込んだ値で、#34 で索引が無くなったあとも残っている。
1回目の [`hugefree_need`](../hugefree_need/) は、`impl/38_precheck` の完走1本のあいだに **2 MiB 以上の空きブロックがどれだけ減るか**を「消費量」として測ったが、
消費量が本ごとに 1.79〜4.51 GiB と 2.52 倍違い、決めた手順どおり基準を決めずに止めた。

1回目の回したあとの読みでは、小さな確保（4 KiB のページ・ページキャッシュ）は、まず 2 MiB 未満の空きブロックから取られ、それが尽きてから 2 MiB 以上の塊が割られる。
だから 2 MiB 以上の減りは、走るノードに 2 MiB 未満の空きがどれだけ残っていたかで動き、1本が実際に要る量を少なく見積もる。

**2回目は、消費量を「そのノードの空きブロック全体（全部の大きさ、order 0〜10）の減り」で測る。** これは「走る前に 2 MiB 未満の空きが1つも無かったら、
2 MiB 以上の塊から取られる量」にあたり、ノードの小さな空きの残り具合に左右されにくい。

**走る前の判定は変えない**（`tools/run.sh` も門番も、2 MiB 以上の空きを基準と比べる）。変えるのは、基準の値を決めるための「1本が要る量」の測り方だけ。

## 何を「使う量」とするか（回す前に決めた）

- **主: 消費量** ＝ 走る前の空き − 走っているあいだのその最小値（GiB）。**空きは、そのノードの全部の大きさの空きブロックの合計**
  （`/proc/buddyinfo` の order 0〜10 の個数 × 4 KiB × 2^order を、zone を足して合計したもの）。`pin` はノード0、`free` はノード0・ノード1・両ノードの合計
  （合計は読みごとに足してから最小を取る）。走る前の値は `logs/<ラベル>_before.txt` の写し、走っているあいだは 0.2 秒おきの読み
- 並べて出す: 1回目の定義（2 MiB 以上の空きの減り）、持ち越し（走る前 − `dat/` を消したあと。全部の大きさと 2 MiB 以上の両方）、最小が起きた段、
  `AnonHugePages` の最大、`thp_fault_alloc`・`thp_fault_fallback`・`compact_stall` の前後差、ピーク RSS、段ごとの秒（参考）
- 空き全体の減りには、計測機のほかの動き（ほかのプロセスのページキャッシュなど）も入る。回す前に、ほかの計算が動いていないことを確かめる

## 測り方

1回目と同じ（スクリプトは 1回目の写し。違いは下の1つだけ）。

- [`sampler.py`](sampler.py): 0.2 秒おきに、両ノードの 2 MiB 以上の空き（1回目と同じ列）に加えて、**全部の大きさの空きの合計**（`node*_all_gib`）と、
  **order 0〜10 の個数**（`node*_orders`。後から別の数え方で読み直せるように）を書く。読むだけで、計測される側には手を入れない
- [`run_one.sh`](run_one.sh)・[`run_all.sh`](run_all.sh)・[`check_answer.py`](check_answer.py)・[`lib.sh`](lib.sh) は 1回目の写し（作業の置き場所だけ `runs/hugefree_need2/`）
- 道具の動作は、回す前にダミーのプロセスで確かめた。[`summary.py`](summary.py) は 1回目のログに仮の列を足した写しで動くことだけを確かめた（数は使っていない）
- 取りこぼしの見込みは 1回目と同じ（1回の読みの間に減る量は多くて 0.5 GiB ほど）

## 本数と並び（回す前に決めた）

1回目と同じ。`pin`（門番と同じ `numactl --cpunodebind=0 --membind=0`）3本・`free`（固定しない）2本を、**`p1_pin`・`f2_free`・`p3_pin`・`f4_free`・`p5_pin`** の順に。

- 1本目の前に、今の基準と比べる量（`pin` はノード0、`free` は両ノードの合計の、2 MiB 以上の空き）が 16 GiB 以上あることを確かめる。足りなければ回さずに本人に知らせる。
  **5本のあいだはキャッシュを落とさない**。2本目からは、16 GiB を割っていても止めずに走らせ、「今の基準なら止まっていた」と残す
- 各本の答えの検査: `dat/` の md5 一覧の sha256 が #38 本走と同じ（`a982b554596c…`）、オラクル174行。`dat/` は本ごとに消してから次へ
- 回す前に、CPU 使用率（全 CPU）が 3% 以下であることを確かめ、load average と CPU 使用率だけを残す

## 新しい基準の決め方（回す前に決めた）

式と止め方は 1回目と同じ。消費量の定義だけが上のとおり替わる。

- **新しい基準 ＝ `pin` 3本のノード0の消費量の最大 × 1.5 を、GiB の整数に切り上げたもの**。ただし `free` 2本で、どちらかのノードの消費量がそれ（`pin` の最大）を超えたら、
  そちらの最大で同じ計算をする
- 1.5 の理由: 3本しか見ていないことと、0.2 秒おきの取りこぼし（1回目と同じ）
- 新しい基準は、門番（ノード0の 2 MiB 以上の空きで比べる）と `tools/run.sh`（両ノードの合計で比べる）の両方の既定値にする。消費量は「2 MiB 未満の空きが無いとき」の量なので、
  走る前に 2 MiB 以上の空きをこの基準と比べれば、2 MiB 未満の空きの残り具合によらず足りる側に倒れる
- 止める（基準を決めない）:
  - **新しい基準が 16 GiB 以上** → 基準は変えずに止めて報告する
  - **消費量が本ごとに大きく違う**: 5本の「その本の消費量」（`pin` はノード0、`free` は両ノードの合計）の最大が最小の2倍を超える → 基準を決めずに止めて報告する

## 止める条件（回す前に決めた）

1. どれかの本で答えの検査が外れる
2. どれかの本で `thp_fault_fallback` の前後差が 0 でない
3. 上の「新しい基準が 16 GiB 以上」「消費量が本ごとに大きく違う」
4. 1本目の前の空きが 16 GiB に満たない（キャッシュは本人が落とす）

### 言えないこと

- 0.2 秒より短い山は読めていない（1回の読みの間に減る量は多くて 0.5 GiB ほどと見たが、確かめていない）。余裕の 1.5 倍（8 GiB − 5.25 GiB ＝ 2.75 GiB）はその見込みの5倍ある

- 測ったのは `impl/38_precheck` だけ。大きな表や配列を足す・替える記録のあとは、この手順で測り直す必要がある
