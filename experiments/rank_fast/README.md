# rank_fast: 番号の計算 `rankOf` が F1 と後退解析でどれだけ時間を使っているかを測り、番号の値を変えずに軽くする試作を比べる（記録試行ではない）

番号を取らず、`impl/39_*` を作らず、`results/` にも README の記録表にも載せない。完走の門番・本走はしない（推すところまで）。
`impl/38_precheck` そのものは触らない（写しにパッチを当てる）。

## 目的

[`perf_38`](../perf_38/) で、#38 の F1（600 cycles / 局面）のうち **`rankOf`（局面の番号の計算）に 188 cycles / 局面（31%）** が付いた。
生成器（262）とほぼ同じ重さ。`rankOf` は F1 の後続ごとのほか、後退解析の `U_loop` でも前任の候補ごとに、`U_draw` でも未知局面ごとに呼ばれている。
軽くできれば両方の段に効く。

`rankOf` は分岐の無い表引きの鎖になっている（`impl/38_precheck/animal_shogi.c` の 382〜417 行）:
ライオン2頭のマス（`rankFindKoma` × 2）→ `g_rank_lion` → 盤の反転とライオンのマスを抜いて詰める（`rankSqueeze` × 2）→
前半・後半それぞれ `g_rank_pair` × 2 と `g_rank_code` → `g_rank_half`（59,049 欄 × 4 バイト ＝ 236 KB）→
前後の組で `g_rank_split`・`g_rank_rmul`・`g_rank_hand` → 掛けて足す。
`g_rank_half` は計測機（Broadwell）の L1（32 KB）に収まらない。重さが、表引きの待ちが鎖の段数ぶん積み重なることなのか、
L2 まで取りに行く待ちなのか、計算そのものなのかは、まだ測っていない。

2段に分ける。

1. **段1（調べる）**: `rankOf` が F1・`U_loop`・`U_draw` でそれぞれ何 cycles / 呼び出し・何秒を使っているか、`rankOf` の中のどこで時間を使っているかを測る
2. **段2（試作）**: 段1の結果をもとに、**番号の値を1つも変えずに** `rankOf` を軽くする試作を作り、生成器だけのベンチで `base` と比べる。
   段2の作りは、段1の結果と一緒にあとのコミットで登録する

**番号の値を変えない**ことがこの実験の前提。値が同じなら `g_seen`・`g_prep`・`g_dtm` の添字が同じなので、記録にしたときに `dat/` が #38 とバイト一致する。

## 回す前に数えたもの

`impl/38_precheck` の Makefile の gcc 行に `-g` を足して組んだ `.so`（[`build_arm.sh`](build_arm.sh) の `g/`。`.text` は `-g` なしとバイト同一）で、
`addr2line -i` のインライン展開の鎖に `rankOf` を含む命令を関数ごとに数えた（回す前。標本は使っていない）。

| 関数 | `rankOf` の命令 | 展開の数 |
|---|---|---|
| `nextBoardSeenNormal`（F1） | 138 | 1 |
| `unmoveStep`（`U_loop`） | 137 | 1 |
| `unmoveDraws`（`U_draw`） | 274 | 2（先頭の 16 個と本体） |

`nextBoardSeenNormal` の番号を出すループ（762〜763 行）は1周 141 命令で、そのうち `rankOf` でないのは入力の読み・番号の書き出し・先読み・ループの判定。
表の読みは 15 回（`g_rank_lion` 4・`g_rank_pair` 4・`g_rank_code` 2・`g_rank_half` 2・組の表 3）、掛け算（`imul`）は 6 回。

`rankOf` の呼び出しの数は、どれもリポジトリにある #38 本走の記録から出る（`results/38_precheck/`）:
F1 は後続の数 ＝ `forward.tsv` の `n_new_pre` の和 938,671,869（3.803 / 局面）、`U_loop` は `main.log` の「前任の候補」578,723,910、
`U_draw` は未知局面の数 ＝ `main.log` の「総未知盤面数」99,485,568。

## 段1の測り方（回す前に決めた）

### 1-1. 本物の完走での割合（`perf record`）

`impl/38_precheck` の写しに2つのパッチを当てた腕で完走させる（[`build_arm.sh`](build_arm.sh)、[`run_one.sh`](run_one.sh)）。
`.so` は記録 #38 の `.so` とバイト一致することを毎本見る（sha256 の先頭 `a712601ee2c9`）。

- [`perf_34` の `patches/perf_ctl.patch`](../perf_34/patches/perf_ctl.patch)（写さずに当てる）: F1 と `U_loop` の境界で perf に `enable` / `disable` を送る。
  `U_loop` で展開した局面の延べ数をログに1行足す
- [`patches/u_draw_ctl.patch`](patches/u_draw_ctl.patch)（その上に当てる）: **`U_draw` も同じ作りで足す。** `PERF_CTL_U_draw` / `PERF_ACK_U_draw` を読み、
  `_profMark("U_loop")` の直後に `enable`、`_profMark("U_draw")` の直前に `disable` を送る。数える範囲は `unmoveDraws` とその結果の写し
  （段の計時の `U_draw` とほぼ同じ）
- どちらも `animal_shogi.py` だけを変える。perf は3つ: F1 は起動した perf、`U_loop` と `U_draw` は python に `-p` で付けた perf（`perf_34` の `U_loop` と同じ付け方）。
  3つとも `-D -1`（止めた状態で始める）と `--control fifo:`
- 取るイベントは3つで、どれも `pp`（PEBS）と `-d`（ロードの番地）。周期は素数で、イベントごとに `cpu/…,period=…/` で書く（`perf_38` で直した書き方）:

| イベント | F1・`U_loop` の周期 | `U_draw` の周期 |
|---|---|---|
| `cycles` | 2,000,003 | 400,009 |
| `mem_load_uops_retired.l1_miss` | 2,003 | 20,011 |
| `mem_load_uops_retired.l2_hit` | 2,003 | 20,011 |

- 周期の選び方: F1 は約 1.5 × 10^11 サイクルで cycles の標本は 7 万個ほど（毎秒 1,700 個）。`U_draw` は 1.8 秒なので周期を5分の1にして 1.5 万個ほど（毎秒 8,500 個）。
  L1 の外れは `perf_34` / `perf_38` で F1 1.4 / 局面・`U_loop` 3.3 / 局面（#34）なので、周期 2,003 で毎秒 4,000〜5,000 個。`U_draw` は数えたことが無いので周期を10倍にした。
  カーネルの標本の上限（`kernel.perf_event_max_sample_rate`、いまは 14,000）は変えない。間引き（THROTTLE）と取りこぼし（LOST_SAMPLES）は本ごとに残す
- 3つのイベントは汎用のカウンタを3つ使う（`cycles:pp` はこの CPU では汎用で数える）。多重化が起きたかは record では直接出ないので、
  **cycles の標本の数 × 周期 ÷ 区間の秒**（実効の周波数）を本ごとに出して、3.2〜3.5 GHz の範囲にあるかで見る（多重化すると下がる）
- 標本は [`attribute.py`](attribute.py) で、`-g` なしの `.so` の逆アセンブルで番地に直し（`perf_branch_34` の `branches.py` の `resolve`）、`-g` の `.so` の
  `addr2line -i` で**インライン展開の鎖を全部**と一番内側のソースの行に寄せる。`rankOf` はどこでもインライン展開されているので、鎖に `rankOf` を含む標本を `rankOf` とする
  （`rankFindKoma` は `unmoveRaw` とキャッチの先行判定でも展開されるので、一番内側の関数の名前だけでは決めない）
- ロードの標本は `-d` の番地を `.so` の静的な表の記号（`nm`）に寄せ、**どの表の読みが L1 で外れたか・L2 で当たったか**を出す
  （`.so` を読み込んだ先頭は、標本の命令の番地 − その命令のリンク時の番地）
- 3本（r1〜r3、同じ腕を3回）。`numactl --cpunodebind=0 --membind=0`

`rankOf` の中の区分（行 → 区分。一番内側の関数と行で決める。行番号は `impl/38_precheck/animal_shogi.c`）:

| 区分 | 行 | 中身 |
|---|---|---|
| ライオンのマスと `g_rank_lion` | `rankFindKoma` 382〜386、`rankOf` 402・403 | 2頭のマスを探して `g_rank_lion` の欄を指す |
| 反転と詰め | `rankOf` 405・406・407、`rankSqueeze` 389〜392 | 鏡像の盤を作って選ぶ（`lt->mirror` の読みは 406）、ライオンのマスを抜いて詰める（`lt->hi` / `lt->lo` の読みは 407） |
| `g_rank_pair` | `rankHalf` 394〜396 | 5マスを9進数にする（`g_rank_pair` × 2 と `g_rank_code`、掛けて足す） |
| `g_rank_half` | `rankOf` 408〜411 | `g_rank_half` × 2 と、結果から組を取り出す（`s0` / `s1`。読みの待ちはその使い手に付くことがある） |
| 組の表 | `rankOf` 412・414 | `g_rank_hand`、`g_rank_split`・`g_rank_rmul` と `lt->base` の読み（414 は前半の順位 × `rmul` の掛け算も含む） |
| 掛けて足す | `rankOf` 413・415・416 | 後半の順位 × 通り数、持ち駒の部分、足し合わせ |
| `rankOf`: ほか | 上に無い行 | |

- 区分は行で分けるので、1つの行に読みと計算が混ざるところ（406・407・414）は混ざったまま。待ちの標本は、待っている読みそのものか、その結果を使う命令に付く

### 1-2. `rankOf` だけのベンチ（待ちと計算を分ける）

[`rank_glue.c`](rank_glue.c)（腕の `animal_shogi.c` をそのまま取り込み、入力を作る関数と `rankOf` を回す関数を足したもの）を、
`impl/38_precheck` の Makefile の gcc 行のまま `.so` にし（[`build_bench.sh`](build_bench.sh)）、[`rank_bench.c`](rank_bench.c) が `dlopen` して呼ぶ。

- 入力（どちらも本物の並び。`runs/` に残っている `perf_34` の dump の本の入力）:
  - **fwd**: F1 の各ラウンドの真ん中の連続した 4,096 局面（`f1_*.bin` 74 個）を `nextBoardInvNormalNC` に通した後続を、出てきた順に並べた列
  - **unmove**: `U_loop` の各段の真ん中の連続した 4,096 局面（`u_*.bin` 174 個）を `unmoveCandidates` に通した前任の候補を、出てきた順に並べた列
  - #37 から全探索の並びは #34 と同じ（全探索の側の `dat/` がバイト一致）。後退解析は #37 で候補の並びが変わったので、各段のフロンティアの集合は同じだが並びは #34 のもの
    （`unmove_gen` のベンチと同じ入力）
- 回し方（どれも呼び出しの数 1 億に届くまで列を何周も回す。周の数は 1 億 ÷ 列の長さの切り上げ）:
  - **none**: 列を作るだけで番号を出さない（固定の分。ほかから引く）
  - **thr（続けて回す）**: 列の番号を順に出して足すだけ。呼び出しどうしは独立で、CPU が並べて処理できる
  - **chain（鎖にして回す）**: 前の番号と `mask`（実行時に 0 になる引数）の AND を次の盤に xor で混ぜる。盤は変わらないが、1呼び出しずつしか進めない。
    鎖には `and` と `xor` の2命令ぶん（約 2 サイクル）が足される
  - **small（小さい集合）**: 列の真ん中の 64 個だけを thr と同じく回す（表の欄が L1 に残る）
- `perf stat -e cycles:u,instructions:u,mem_load_uops_retired.l1_miss:u,mem_load_uops_retired.l2_hit:u`。7周、`numactl --cpunodebind=0 --membind=0`。
  周ごとに回し方（thr・chain・small）の順を1つずつずらす。入力ごとに none を先に回す（[`run_rankbench.sh`](run_rankbench.sh)）
- thr と chain は同じ列なので、番号の和（検算）が同じになることを見る

## 段1の式（回す前に決めた）

[`summary1.py`](summary1.py) が生ログから作る。どれも3本の中央値と範囲（最小〜最大）。

- 区間の cycles ＝ その区間の cycles の標本の数 × 周期
- `rankOf` の割合 ＝ 鎖に `rankOf` を含む cycles の標本 ÷ その区間の cycles の標本（`.so` の外・カーネルも分母に入れる）
- **`rankOf` の秒 ＝ 割合 × 区間の秒**（F1 は `forward_summary.tsv` の F1、`U_loop` と `U_draw` は `retreat_summary.tsv`）。
  **全部ただになったときの上限**として読む（呼び出し側の読み書きと重なって隠れていた分は、ただにしても戻らない）
- `rankOf` の cycles / 呼び出し ＝ 割合 × 区間の cycles ÷ 呼び出しの数（F1 は `n_new_pre` の和、`U_loop` は「前任の候補」、`U_draw` は「総未知盤面数」）
- 区分ごとの cycles / 呼び出しも同じ式で、分子をその区分の標本にする
- 表ごとの L1 の外れ / 呼び出し ＝ 鎖に `rankOf` を含み、番地がその表にあるロードの標本 × 周期 ÷ 呼び出しの数（L2 で当たったものも同じ）
- ベンチの1呼び出しあたり ＝ （その回し方の値 − 同じ周の none の値）÷ 呼び出しの数。周ごとに取ってから7周の中央値と範囲

## 主因の決め方（回す前に決めた）

本物の `rankOf` の cycles / 呼び出し（R）を、ベンチの3つの値で3つに分ける。F1 と `U_loop` を別々に分け、呼び出しの数で重みを付けて合わせたもので決める
（`U_draw` はベンチの入力が無いので、秒にだけ入れる）。

| 部分 | 式 | 意味 |
|---|---|---|
| 計算 | small | 表が L1 にあって、呼び出しが独立なときの重さ（命令の数と演算器の取り合い） |
| L2 の待ち | thr − small | 本物の並びの入力で表の欄が L1 から外れる分 |
| 重ねきれない分 | R − thr | 本物の文脈で、呼び出しどうし・まわりの仕事と重ならずに鎖の待ちが表に出る分（chain − thr はその上限の目安） |

- **一番大きい部分を主因とする。** 対応する試作の考え方: 計算 → 命令を減らす、L2 の待ち → `g_rank_half` を L1 に収まる小さな表に分ける、重ねきれない分 → 鎖の段を減らす・並べ替える
- 2番目の部分が R の 20% 以上なら、段2の2本目の試作はその考え方にする（20% 未満なら試作は1本）
- 一番大きい部分が R の 40% に満たないときは、主因が決められないとして段2に進まない（止める条件 4）
- 裏付けとして、本物の `g_rank_half` の L1 の外れ / 呼び出しと、ベンチの thr の L1 の外れを並べる（L2 の待ちが主因なら、どちらも 0.3 / 呼び出し以上あるはず）

| **主因** | **計算**（small が R の 60〜80%）。2番目は重ねきれない分（R の 15〜30%）、L2 の待ちは R の 10% 未満 | R ≈ 49、small ≈ 35、thr ≈ 38 と見る |
