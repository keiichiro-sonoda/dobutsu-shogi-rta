# unmove_flip: 逆向きの生成器で、盤の反転を局面ごとに1回にする（記録試行ではない）

番号を取らず、`impl/` を作らず、タイムを `results/` にも README の記録表にも載せない。

**工夫は1つだけ入れる。** [`unmove_prune`](../unmove_prune/) の絞った版の逆向きの生成器を土台にして、反転の位置だけを替える。
正規形の判定のしかた、作る前の絞り込み、到達しない候補の扱い、展開の順番は変えない。あわせて、これまで未計測だった
「試作の後退解析の結果を成果物の形へ書き出す費用」を測る（新しい工夫ではなく、換算の穴を埋める計測）。

## 目的

`unmove_prune` で、作り替えた後退解析の見積もりは 74.79 秒になり、いまの P1 ＋ P2 ＋ P4 ＋ 174段ループ（#33 本走、76.70 秒）と並んだ（−1.92 秒）。
この差は、同じ関数を別の日に測ったときのずれ（`unmove_prune` の `naive` が `unmove_catch` より 2.0%）と同じくらいの大きさで、まだ速いとは言えない。

絞った版は、手を指した直後の盤 nb（q か、その鏡像）の上で手を戻し、**戻した候補ごとに `invBoard` を通して**前任 p の形に直している
（正規形でないとして捨てる戻し方の分も含めて）。前向きの生成器（`nextBoardInvNormal`）は局面の頭で1回だけ反転し、反転した盤の上で手を指すので、
後続ごとの反転は無い。逆向きも同じ形にして、候補ごとの反転を無くす。

## 反転した盤の上での手の戻し方（[`flip.c`](flip.c)）

`invBoard` は、マス a（番地。a ＝ 16 × 列 ＋ 4 × 行）を 44 − a へ移し、駒のあるマスの持ち主のビット（0b1000）を反転し、持ち駒の2組
（bit 48〜53 と 54〜59）を入れ替える。絞った版では p ＝ `invBoard`(b′)（b′ は nb で手を戻した盤）なので、先に f ＝ `invBoard`(nb) を作って
f の上で手を戻せば、戻した盤がそのまま p になる。f では、直前に指した側 X の駒が 1〜5、X の持ち駒が bit 48〜53、q の手番側 Y の駒が 9〜13。

規則の正本は `nextBoardInvNormal`（とそれを写した `unmove.c` の `unmoveRaw`）。写し方は次のとおり。

- 44 − a ＝ 16 × (2 − 列) ＋ 4 × (3 − 行) なので、a % 16 は 12 − a % 16 に替わる
- **動かした手**: nb で s から d ＝ s ＋ m（m は移動表の値）へ動いた手は、f では s′ ＝ 44 − s から d′ ＝ 44 − d ＝ s′ − m へ。戻すと **s′ ＝ d′ ＋ m**
  （0〜44 の外は捨てる）。移動表は、X のきりん・ぞう・ライオン・にわとり（f では `GIRAFFE1`〜`CHICKEN1`）にそれぞれ同じ表を使う
- **回り込みの2条件**: nb の（s % 16 ＝ 0 かつ d % 16 ＝ 12）と（s % 16 ＝ 12 かつ d % 16 ＝ 0）は、% 16 が 12 − (% 16) に替わるので
  f では（s′ % 16 ＝ 12 かつ d′ % 16 ＝ 0）と（s′ % 16 ＝ 0 かつ d′ % 16 ＝ 12）。2つの組は同じ形のまま入れ替わるだけ
- **ひよこ**: nb の X のひよこは d ＝ s − 4 へ進み、d % 16 が 4 か 8 なら成らない手。f では d′ ＝ s′ ＋ 4、d′ % 16 が 8 か 4 なら成らない手で、
  戻すと s′ ＝ d′ − 4
- **成りを戻す**: nb では d % 16 ＝ 0 のにわとりが s ＝ d ＋ 4 のひよこから成った手もありうる。f では **d′ % 16 ＝ 12** の `CHICKEN1` が s′ ＝ d′ − 4 の `CHICK1` から
- **打った手を戻す**: X の持ち駒を1つ増やす。f では X の持ち駒が bit 48 からなので、駒 k（`CHICK1`・`GIRAFFE1`・`ELEPHANT1`）は bit 48 ＋ 2 × (k − 1)。
  増やし方の式（0 → 1 は `^0b01`、1 → 2 は `^0b11`）は同じ
- **取った駒を戻す**: Y の駒 c を d′ に **c | 8** で置き、X の持ち駒を1つ減らす。f では c ＝ `CHICKEN1` なら bit 48（ひよこと同じ欄）、ほかは 46 ＋ 2c
- **鏡像**: 列の入れ替え（`unmoveMirror`）と `invBoard` は入れ替えられる（`invBoard` は列 c を 2 − c、行 r を 3 − r へ。鏡像は列 c を 2 − c へ。
  持ち駒は鏡像で変わらない）。だから **q ごとに `invBoard` は1回だけ**にし、鏡像の側は f の鏡像を作る。q が左右対称 ⇔ f が左右対称
- **正規形の判定**（`normalBoard(p) == p` を候補ごとに見る）は変えない

**絞り込みの写し方。** A（q で Y に王手をかけている X の駒のマスの集合。盤の列 A〜C とは関係ない）は、**f の上で作り直す**。f では Y のライオンが
`LION2`、X の駒 k はマス s から s − m へ利き（nb の s ＋ m を裏返したもの）、回り込みの2条件は上と同じ、X のひよこ（`CHICK1`）は s ＋ 4 へ
（s % 16 ＝ 12 なら利かない）。この表は `attack_count` の `g_att` と同じ形になる。判定のしかた（A が2マス以上なら何も作らない、1マスならそのマスの駒だけ、
戻した先から Y のライオンに利く戻し方は作らない）は絞った版と同じ。

候補の順番は変わる（f のマスの順に駒を見るので）。試作の後退解析の展開の順番（フロンティアの順）は変えない。

## 一致の検査（[`run_verify.sh`](run_verify.sh)、[`bench.c`](bench.c) の `verify`）

全到達局面（246,803,167）の q ごとに見る。

- **(0) 写しの確かめ**: 一致の検査のために、絞った版を「正規形でないとして捨てた数」と「候補ごとの A の大きさ・nb が q か鏡像か」を数えながら作る写し
  （`unmovePrunedCounted`。`prune.c` の関数は数えを持たないので写した）を作った。その候補の列が `unmovePrunedCandidates` と順番まで同じこと。
  反転を1回にした版の数える口（`unmoveFlipCounted`）も、計時する口（`unmoveFlipCandidates`）と順番まで同じこと
- **(a) 候補の多重集合が、絞った版と同じ**（件数とハッシュ2つ）。戻した手の種類（動かした・取った・打った・成った・成って取った）× A の大きさ（0 / 1）×
  nb が q か鏡像か、の区分ごとにも比べ、食い違いは区分ごとに数える
- **(b) 前任の多重集合が、絞った版と素朴な版と同じ**（`unmoveFlipSieved`・`unmovePrunedSieved`・`unmoveSieved`）
- **(c) 正規形でないとして捨てる候補の数と、到達しない（`cls` が 0）として捨てる候補の数が、絞った版と同じ**

### 正解の取り方がこれで足りる理由（回す前に考えた）

`unmove_prune` で外れたのは、「捨てた候補がキャッチ局面か」の正解を `cls` で引いたからだった。`cls` は到達局面にしか種類を持たないので、
`cls` を通した正解は、到達しない候補について正しくない。

- 今回の (a)・(b) の正解は**絞った版が作ったもの、そのもの**で、値（局面のパック値）で比べる。`cls` を通さないので、到達しない候補も、キャッチ局面の形の候補も、
  そのまま値として突き合わさる。表し方を替えただけなら候補は1つも増減しないはずなので、多重集合の一致がそのまま確かめたいことになる
- (c) の「到達しないとして捨てる数」は `cls` を引くが、両方の版の候補に同じ表を同じように引いて数を比べるだけで、`cls` を正解に使っていない
  （(a) が通れば自動で通る。(a) が外れたときに、どこで外れたかを見る手がかり）
- 正解の側（絞った版）そのものの正しさは、`unmove_prune` で確かめてある: 前任の多重集合が素朴な版と同じ（素朴な版は `unmove_bench` で前向きの辺と同じ）、
  捨てた候補は全部生成器でキャッチ局面。(b) では素朴な版とも直接比べる
- 数える写し（`unmovePrunedCounted`）が、計時する絞った版と違うものを作っていたら (a) の意味が無くなるので、(0) で順番まで突き合わせる
- 足りないもの: 候補の多重集合の一致は「後退解析の答えが変わらない」の十分条件だが、試作の後退解析の側の書き換え（`flipStep`）の誤りは見ない。
  それは計時の各本で、全局面の手数を `dat/` と比べて確かめる

## 成果物の形へ書き出す（`bench.c` の `retreat` の後半）

試作の後退解析のループのあとで、いまの `dat/` と同じファイルの分け方で書き出す（ループの秒には入れない）。いまの実装（`animal_shogi.py` の
`writeWLFilesForDepth`・`writeUnknownChunks`）と同じ分け方: 手数と勝敗ごとに、空いている副番号から 5,000,000 局面ずつのファイル。0 件でも副番号 0 が
無ければ空のファイルを作る。引き分けは `unknown<番号>.bin`。中身は 8 バイトのパック値の並び。ファイルの中の並びは揃えない。

| 測る区間 | 中身 | 換算に |
|---|---|---|
| 全探索の側 | キャッチ局面（`win001te_000`〜）とトライ負け（`lose000te_000`〜）。いまの実装では全探索が書く | 入れない |
| 手数ごと | ループで決まった局面を、手数ごとのファイルへ（`found` の列を手数の区切りで書くだけ） | 入れる |
| 引き分けを拾う | 未知局面の列 U（全探索が作る）を順に見て、ランクで `dtm` を引き、未定のものを集める（16 個先のランクを出して `dtm` の行を取り寄せる） | 入れる |
| 引き分けを書く | 引き分けを `unknown<番号>.bin` へ | 入れる |

- **書き出し先**は `runs/unmove_flip/out/`（git に入れない。読む `dat/` と同じファイルシステム）。各本の前に消して `sync` し、前の本の書き戻しを済ませてから回す。
  `fsync` はしない（いまの実装も Python の `write` だけ）ので、測るのはページキャッシュへ書くまで。ディスクへの書き戻しはあとで非同期に起きる
- **いまの作りで同じ役目をしている段**: 手数ごとの書き出しは、いまの実装では 174段ループの中（段ごとに `gatherPacked` と `writeWLFilesForDepth`）にあって、
  ループの秒（`loop174` 14.54 秒）から分けられない。引き分けは `R_draw`（0.23 秒）と `R_uk`（0.06 秒）（#33 本走の `results/33_hot_layout/retreat_summary.tsv`）。
  だから比べる相手は「いまの4段 ＋ `R_draw` ＋ `R_uk`」（76.99 秒）で、手数ごとの書き出しの分はいまの側にもう入っている
- **成果物の確かめ**（[`check_out.py`](check_out.py)、各本のあと）: ファイルの名前の集合とファイルごとの件数が #33 本走の `dat/` と同じ、手数ごとの件数が
  `oracle/distribution.tsv` と同じ、指紋（手数ごとの件数・総和・XOR）が `oracle/fingerprint.tsv` と同じ（`tools/fingerprint_dat.py --against`）。
  #33 本走の `dat/` 自身に当てて PASS することを、回す前に確かめた（49 秒）

## 条件

これまでの実験（`unmove_bench`・`unmove_catch`・`attack_count`・`unmove_prune`）と揃えた。

- 入力は #33 本走の `dat/`。`cls.bin` と計時用の抜き出しは `unmove_prune` と同じ作り方・同じシードで `runs/unmove_flip/` に作り直す（sha256 を `logs/prep.txt` に残し、
  `unmove_prune` の `logs/prep.txt` と同じ中身であることを見る）
- `.so` は `impl/33_hot_layout` の `Makefile` の `gcc` 行のまま（入力と出力の名前だけ替えて）ビルドする（[`build_so.sh`](build_so.sh)）。`unmove.c`・`catch.c`・`prune.c` は
  書き換えずに写して取り込む（`prune.c` は `unmove_prune` で測ったあとにコメントを1行足した版。コードは同じ）。ベンチ本体は `dlopen` して呼ぶ（`RTLD_LOCAL`）
- 計時はどの本も `numactl --cpunodebind=0 --membind=0` で固定。`cls`・状態の配列・`dtm`・`cnt`・`found` は 2 MiB の区切りで確保して `madvise(MADV_HUGEPAGE)` を頼む。
  先読みは両方の版で同じ（候補のランクで `cls` の行を、残った前任で状態の行を取り寄せる）。周波数の標本と、前後の `thp_fault_fallback` を残す
- **回す前に巨大ページに使える空きを確かめてファイルに残す**（`lib.sh` の `free_snapshot` が `logs/free.txt` に足す）。生成器の計時の前と、後退解析の各本の前。
  ノード0の 2 MiB 以上の空きブロックが 12 GiB に満たなければ止める（キャッシュを落としてもらってから起動し直す）
- 回す前の負荷は load average と CPU 使用率の合計だけを残す

### 測るもの

1. **生成器だけ**（[`run_time.sh`](run_time.sh)）: `cand`・`sieve`・`visit` の3段階を、絞った版（`pcand`・`psieve`・`pvisit`）と反転を1回にした版
   （`fcand`・`fsieve`・`fvisit`）で。`unknown`・`try`・`expand` の列、6つの版を5周、周ごとに順番を1つずつずらす。各列を1周温めてから1周測る
2. **試作の後退解析を丸ごと**（[`run_retreat.sh`](run_retreat.sh)）: `unmove_prune` の `pruned`（`pruneStep`）と、生成器だけを入れ替えた版（`flip`。`flipStep`）を、
   `pruned flip flip pruned pruned flip` の順に3本ずつ。毎回、全局面の手数が `dat/` と一致することを確かめ、成果物の形へ書き出して確かめる。
   ループの秒、展開した局面、候補、残った前任、書き出しの4区間の秒を出す

回す順: `run_verify.sh` → `run_time.sh` → `run_retreat.sh`。

### 換算（[`summary.py`](summary.py)）

- 作り替えた後退解析の見積もり ＝ 試作のループ ＋ B1′ の費用（`attack_count`、5.08 秒）＋ 全局面の種類と残りの数をランクの配列に書く費用（`unmove_bench` の
  `degw`、8.96 秒）＋ 書き出しの費用（手数ごと ＋ 引き分けを拾う ＋ 引き分けを書く）。各本で計算して中央値と範囲
- 比べる相手は、いまの4段（76.70 秒）＋ `R_draw` ＋ `R_uk`（合わせて 76.99 秒）
- 同じ回の絞った版でも同じ換算を出す。書き出しを入れない形（`unmove_prune` と同じ形）も出し、`unmove_prune` の 74.79 秒とのずれを書く

## 止める条件（回す前に決めた）

1. **一致の検査 (0)・(a)・(b)・(c) のどれか1つでも外れたら計時をしない**（`run_time.sh` と `run_retreat.sh` が [`gate.sh`](gate.sh) で `logs/verify.txt` の PASS を見る）。
   食い違いを、戻した手の種類・A の大きさ・nb が q か鏡像か、で分けて報告する
2. **試作の後退解析で、どちらかの版の手数が1局面でも `dat/` と食い違ったら、そこで止める**（`run_retreat.sh`）
3. **書き出した成果物の確かめが1本でも外れたら、書き出しの費用を換算に使わない**（止めずに続ける。`summary.py` が見る）
4. 回す前にノード0の巨大ページに使える空きが 12 GiB に満たなければ止める（`free_snapshot`）

## 比べ方（回す前に決めた）

- 生成器だけ: ns/局面は5周の中央値と範囲。反転を1回にした版 − 絞った版は、段階ごとに同じ周どうしの差を取ってから中央値と範囲
- 試作の後退解析: 版ごとのループの中央値と範囲（3本）。差は並びの隣どうしの組（1-2、4-3、5-6）で取り、中央値と範囲
- 書き出しの費用は版ごとに中央値と範囲（版によって変わらないはずなので、6本をまとめても読む）
