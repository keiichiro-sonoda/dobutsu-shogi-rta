# 記録したアテンプトのログ置き場

README の記録表に載せた実行それぞれについて、証拠をここに残す。

```
results/<番号>_<ラベル>/
    env.txt         実行時のマシン構成と、何を計測したか
    main.log        完全解析のメインログ (verify_log.py に通したもの)
    time.txt        /usr/bin/time -v の出力
    verify.txt      オラクル検証の結果
    fingerprint.txt 直前の記録との成果物照合 (集計経路を変えたときだけ)
    bytecompare.txt 直前の記録との dat/ のバイト比較 (区切りが動かない変更のときだけ)
    freq.log        計測中の CPU 周波数・温度・スロットル回数 (記録 #5 以降)
    forward.tsv         全探索のラウンドごとの内訳 (記録 #10 以降)
    forward_summary.tsv 同・全体のまとめ
```

`fingerprint.txt` は `tools/fingerprint_dat.py` の出力。オラクルは手数別の**局面数**しか
見ないので、実装の集計経路を書き換えたときは `dat/` そのものを突き合わせて
「どの局面がどの手数か」まで確かめる。

`bytecompare.txt` は指紋より強い検査。チャンクの区切りも要素の順序も動かさない変更
（記録 #9 の再スライス撤去）では `dat/` が直前の記録と**バイト単位で**一致するはずなので、
`diff -rq` と md5 の一覧で突き合わせる。区切りが動く変更には使えない（指紋に戻る）。
⚠️ **集合の反復順が変わる変更でも使えない。** 記録 #10 は `a -= b` を `a = a - b` に
変えたので、同じ盤面集合でも pickle の並びが変わる。こういうときは指紋で照合する。

`forward.tsv` / `forward_summary.tsv` は全探索の区分ごとの内訳（F0 読み込み / F1 展開 /
F2 未知の書き出し / F3 集合化 / F4 重複排除 / F5 未探索の書き出し / F6 終端の書き出し）。
後退解析の P0〜P4 と同じ扱いで、記録 #10 から実装に常設した。
⚠️ **`main.log` の F 行は `s2hms()` が秒未満を切り捨てた表示値＝下限。** 正確な値はこの TSV。

`runs/` は .gitignore しているので、記録として残すものだけをここへコピーする
（サブログは巨大になるので入れない）。

`freq.log` は `tools/run.sh` が計測プロセスと並走して1分おきに取る TSV
（`time_jst` / `freq_max_mhz` / `freq_mean_mhz` / `pkg_temp_c` / `throttle`）。

記録 #4 で、**まったく同じ全探索コードが 2430 / 2436 / 2503 秒とばらついた**
（幅 3.0%）。原因は分かっていない。1本の計測で検出できる効果の下限に関わるので、
判断材料になる値だけ残しておく。⚠️ **個々の記録の結論には使わない。**
数本ぶん溜まってから見るためのもの。1スレッドの負荷なので、平均より `freq_max_mhz` を見る
（平均は他コアのアイドルに引きずられる）。⚠️ **ただし解析スレッドがどの論理CPUに乗ったかは
記録していない。** `freq_max_mhz` は全論理CPUの最大で、それが解析スレッドのコアの値だという
確認はしていない。`throttle` も cpu0 の `package_throttle_count`、つまり2ソケットのうち
パッケージ0だけを見ている（`pkg_temp_c` は2ゾーンの最大）。
